## 用户偏好 (7/23 21:10): "以后还是修之前 fork 下"
- **每次修 PR 前主动 fork sync,不是被动等累积**
- 4 步 pre-flight (动手前 30 秒跑完):
  1. `gh api compare ... --jq .ahead_by` 看 fork 是否落后
  2. 落后 >100 commits → `gh api PATCH /git/refs/heads/main` 瞬间同步 (前提 ahead=0)
  3. 看目标 PR 的 base_ref SHA → 是否需要先 rebase
  4. 正式改 PR: 基于同步后 fork/main, 新建分支或 cherry-pick
