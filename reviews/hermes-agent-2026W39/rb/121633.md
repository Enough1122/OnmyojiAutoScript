## Primary: configured ports are discarded

`plugins/platforms/email/adapter.py:528,532,1223` uses a non-zero default from `_esecret_int()` as the left side of `or`, so the `extra` port is never reached when the corresponding `EMAIL_*_PORT` variable is absent. A real `load_gateway_config()` probe preserved `imap_port=1143` / `smtp_port=465` but the adapter resolved `993/587`; standalone sending connected to `587`.

Receipt: https://github.com/NousResearch/hermes-agent/pull/121633#issuecomment-5833829955

## Follow-up: email UID state bypasses profile-aware home

`plugins/platforms/email/adapter.py:617` resolves state with a raw `HERMES_HOME`/`~/.hermes` fallback instead of `hermes_constants.get_hermes_home()`. On Windows, the method resolved `C:/Users/admin/.hermes` while the canonical home was `C:/LocalAppData/hermes`; with a context-local profile override, it kept using the launch home. This splits the newly persisted UID cursor from the active profile.

Open PRs #39486 and #52194 were checked as possible prior art, but both only fix the Google Chat bot-id cache path and do not cover the email adapter path.

Receipt: https://github.com/NousResearch/hermes-agent/pull/121633#issuecomment-5834038723
