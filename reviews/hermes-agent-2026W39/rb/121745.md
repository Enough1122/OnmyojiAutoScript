## What the PR does

Three independent fixes on the API server, no user-facing contract removal:

1. `_sse_headers(request, extra=None)` (api_server.py:1376) centralises the SSE response headers (`Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no` + up-front CORS). Motivation is sound and visible in-tree: `cors_middleware` only touches `response.headers` *after* the handler returns (api_server.py:846-848), and `StreamResponse.prepare()` has already flushed the head by then.
2. Head flush in `_handle_run_events` (api_server_runs.py:1107-1111): `await _write(b": open\n\n")` immediately after `prepare()`, before truncation notice / replay / queue wait. aiohttp otherwise holds the head in the socket buffer until the first body write, so a subscriber on a silent run saw no bytes until the keepalive interval.
3. `tool.completed` + `is_error` now projects as `tool.failed` on `/api/sessions/{id}/chat/stream` (api_server.py:3474-3480), with the api-server.md endpoint table updated in the same commit.
