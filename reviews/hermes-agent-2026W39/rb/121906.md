## Finding

### Post-login Nous picker still omits on-sale models

The PR adds `union_with_nous_on_sale_models` to the already-authenticated `hermes model` flow and GUI/in-chat picker, but omits the same union from `_pick_nous_model_after_login` in `hermes_cli/auth_nous.py:1449-1487`. A paid user signing in (or reauthenticating) reaches that picker immediately (`auth_nous.py:1583-1587`), so `inception/mercury-2.5` and every other discounted model omitted from the curated/Portal-recommended union remains invisible on the primary sign-in completion path.

Reproduction on the exact head:

```text
$ uv run --locked python D:/Hermes/probe121906_login_sale.py
Showing 1 curated models — use "Enter custom model name" for others.
{'selected': 'curated/only', 'picker_model_ids': ['curated/only'], 'sale_present': False}
```

The probe supplies a paid account (`check_nous_free_tier=False`), a one-row curated list, an empty `paidRecommendedModels` response, and a pricing row `vendor/sale` discounted from `1.0` to `0.2`. `_pick_nous_model_after_login` never calls the new union, so the picker receives only `curated/only` even though `hermes model` would list `vendor/sale`.

Suggested fix: import and apply `union_with_nous_on_sale_models` in the paid branch of `_pick_nous_model_after_login`, immediately after `union_with_portal_paid_recommendations` and before policy narrowing; add a regression test for the post-login picker (including free-tier exclusion and tool-less filtering).
