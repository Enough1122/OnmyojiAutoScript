## Finding

**[P1] POSIX `--desktop-only` omits `python-deps`, but the desktop stage re-execs into the environment that stage creates.**

`stage_desktop` delegates to `stage_products` (`install.sh:668-698`), which invokes
`hermes_cli/source_completion.py --desktop`. That entry point re-execs through
`pm.environments.project_python()` into the selected/committed venv
(`hermes_cli/source_completion.py:73-78,130`; `pm/environments.py:151-160,212-214`). With
`python-deps` absent and no prior PM environment record, `project_python` resolves to
`INSTALL_DIR/venv/bin/python`, which desktop-only never creates.

The exact current-head invocation failed in 1.5 seconds with `FileNotFoundError`; fabricating the
PM environment record, changing only that variable, allowed the same command to pass the re-exec
and enter product-build work. The normal Connect-to-existing-Hermes case has no prior PM record,
so the primary POSIX path cannot build the desktop app.

Suggested fix: keep `python-deps` in the desktop-only stage list, or provide a genuinely
non-re-exec desktop build path. A secondary issue notes that `bootstrap.rs:634` still gates the
desktop stage on `args.include_desktop` instead of the new `build_desktop` value.
