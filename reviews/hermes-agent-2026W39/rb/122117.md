## Semantics checked

- **Fail-closed default preserved**: `requested_effort()` returns `None` for
  `enabled is False`, `{}`, or an empty effort, and the helper returns `None` →
  nothing on the wire. `test_unset_effort_sends_no_reasoning_field` and
  `test_unset_or_unmappable_effort_sends_nothing` both hold.
- **Disable is explicit, not implicit**: `enabled is False` maps to
  `{"effort": "none"}` only when `"none"` is in the model's declared set; Astra
  (whose `CODEX_ASTRA_EFFORTS` has no `none`) omits the field instead of 400ing —
  the degradation is documented in the docstring and asserted in
  `test_disable_is_omitted_on_a_model_without_none`.
- **No escalation**: reuses `clamp_effort`, which returns the nearest *weaker*
  supported level; `ultra → max`, `minimal → low`, and gpt-5.5's `max → xhigh`.
  A bespoke level name would pass `clamp_effort` verbatim, so the helper
  re-checks `clamped in supported` and omits rather than emitting an
  `invalid_value` 400. Correct and deliberately defensive.
- **Family isolation**: GPT-OSS is a *different* id family and cannot match
  `gpt-(5|6)`; Claude/Nova/DeepSeek/Grok/Llama also cannot. Asserted across 8
  models × 2 configs. Independently confirmed the only `additionalModelRequestFields`
  write in the tree is the new line 1075 — no pre-existing caller to conflict with.
- **Prompt-cache safety**: the field is derived solely from `model` and the
  configured effort (never from `messages`), so it is byte-stable as history
  grows — `test_reasoning_field_is_byte_stable_as_the_conversation_grows` asserts
  this and the implementation bears it out.
- **One-shot override still works**: the truncation-continuation
  `_ephemeral_reasoning_off` path is upstream of the transport
  (`_reasoning_config_for_wire` at `chat_completion_helpers.py:1283`, consumed at
  `:1516`), so Converse now honors it like every other wire;
  `test_one_shot_reasoning_off_is_sent_then_the_configured_effort_returns` covers it.
- **Retry/self-heal paths unaffected**: `call_converse`'s cachePoint and
  redacted-reasoning recovery both rebuild from the same kwargs dict, so
  `additionalModelRequestFields` is preserved on the resend.
- **Not dead code**: `converse_reasoning_request_fields` and
  `_BEDROCK_OPENAI_GPT_RE` are both absent from the base commit
  (`git grep` on `origin/pr-base` → no match).
