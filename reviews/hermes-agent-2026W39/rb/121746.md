## Finding (1 public carrier)

**[P1] The new `await _submit_api_worker(... _ensure_mcp_tools_registered ...)` at
`gateway/platforms/api_server_runs.py:914` opens a window in which an acknowledged
`/v1/runs/{id}/stop` is silently dropped.**

`_execute_run` checks `self._stopping_run_ids` once at `:911`, then the new blocking await at
`:914` yields the event loop. The set is never re-read — not after discovery, not after
`_create_agent` (`:916`), not before `_run_agent_sync` (`:921`). A `/stop` inside the window hits
`agent is None` in `_handle_stop_run` (`:1173`), so it interrupts nothing but still returns
HTTP 200 `{"status": "stopping"}`; the run then builds its agent and completes the turn anyway.

Window size is bounded by real discovery constants, not theoretical: discovery pass ceiling
`_MCP_DISCOVERY_PASS_MAX_SEC = 300` (`tools/mcp_tool.py:689`), lock-wait budget 320 s
(`tools/mcp_tool.py:690-693`), per-server `_DEFAULT_CONNECT_TIMEOUT = 60` (`:233`). This PR
targets profiles whose `mcp_servers` were never dialled — i.e. the cold, slow path.
