Great refactor — extracting `Subagent.run` removes ~150 lines of duplicated orchestration from the tool plugin and lets v2 commands reuse it. The new `session-command.test.ts` covering child-session creation, job registration, and the parent inbox notification is exactly the right level of test.

A few observations:

1. **Missing subagent preamble on the command path**: the tool plugin wraps prompts with "You are a subagent spawned by another session.", but the command path passes `prompt: evaluated.text` bare. Intentional? If the child behaves differently depending on that framing (e.g., ending its turn early), commands would diverge from tool-spawned subagents.
2. **Unconditional agent lookup**: `agents.get`/`locations.get` is now resolved for *every* command invocation even when `command.agent` is unset. Gating it on `command.agent` presence (as before) avoids the extra service lookups on the common path.
3. **Dead fallback**: inside `if (commandAgent?.mode === "subagent")`, `command.agent` is necessarily defined, so `?? Agent.ID.make("general")` is unreachable — harmless but slightly misleading about the invariant.
4. **Metadata precedence in `notify`**: `{ source: "subagent", ...input.metadata, ... }` means the command path's `{ source: "command" }` overwrites the default. Probably intended for tracing origin, but worth confirming downstream consumers expect either value.
5. Model resolution gained a final `?? session.model` fallback — makes the spawned child always carry an explicit model rather than inheriting server defaults. Fine, just flagging the behavior delta vs. the old `input.model`-only chain.

Nice work overall; nothing blocking.
