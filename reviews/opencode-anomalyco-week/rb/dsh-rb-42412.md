A few things worth a second look:

If remote locations rely on `Updated` to rebuild integration listings/UI state, they'll learn the credential changed without refreshing whatever `Updated` drives. Should it be global too, or is `ConnectionUpdated` genuinely the only signal consumers need?
2. **Refresh now emits events**: the refresh path previously published nothing; it now publishes globally on every token refresh. That fixes cross-location staleness, but with several active locations sharing one credential this could get chatty (each refresh wakes subscribers everywhere). Probably fine — just calling out the volume change.
3. **Ordering guarantee**: in the attempt paths, global `ConnectionUpdated` is followed by local `Updated`. Remote locations see only the first; same-location subscribers see both in order. If any consumer expects the pair atomically, remote behavior will differ subtly.
