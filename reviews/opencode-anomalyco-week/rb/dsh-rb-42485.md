Nice minimal fix — routing local plugin loads through `importModule` instead of raw `await import()` makes sense for SEA builds where plain dynamic import of file paths doesn't behave like it does in dev.

Two small points:

1. **Specifier coverage**: `version` here comes from `freshSpecifier(entrypoint, generation)` / the raw entrypoint. Does `importModule` handle every form that reaches this call site (file:// URLs *and* bare/package specifiers)? If some plugins resolve to non-file specifiers, worth confirming `runtime-import` falls back to standard `import()` for those so behavior stays identical outside SEA.
2. **Type cast**: `(await importModule(version)) as { readonly default?: unknown }` replaces the old checked annotation with an unchecked assertion. If `importModule`'s return type ever drifts, this silently widens what's accepted. Minor, but keeping the shape explicit (e.g. a small typed wrapper in `runtime-import`) would preserve the previous safety.

No objection otherwise — the retry/generation logic below is untouched, which is right for a mechanical load-path change.
