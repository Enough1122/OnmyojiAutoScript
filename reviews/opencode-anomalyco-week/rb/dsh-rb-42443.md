Solid UX improvement — middle-click-to-close matches what users expect from browser/editor tabs, and the full-screen dismiss backdrop fixes the "click outside does nothing" papercut. The two new render tests cover both behaviors nicely, and exporting `TabContextMenu` to make it testable is reasonable.

A few things to consider:

1. **Middle-click on the new-session tab (horizontal)**: `tabs.close(tab === NEW_SESSION_TAB ? undefined : tab.sessionID)` calls `close(undefined)` when middle-clicking the "+"/new tab button. Does that resolve to a no-op, or could it close the *current* tab? Ignoring middle-click on that pseudo-tab entirely seems safer and more predictable.
2. **Backdrop vs. drag-away**: the menu items handle their own `onMouseUp` with `stopPropagation`, so pressing inside and releasing outside lands on the backdrop and just closes — good. But the backdrop only closes on `onMouseUp`, not `onMouseDown`; a quick second right-click on empty space will be swallowed by the backdrop's mousedown before the tab's own right-click handler can re-open/reposition the menu. Minor, but worth a manual check.
3. **originX/originY optionality**: they're optional in `TabContextMenuState` but the backdrop defaults them to 0 (`?? 0`), which would misplace it if any caller ever constructs state without origins. Since both existing call sites set them, making them required would let the compiler enforce that.
4. Consistent `MIDDLE_MOUSE_BUTTON` guards on drag/dragEnd are much appreciated — prevents accidental reorder drags with the middle button.

Nothing blocking beyond the `close(undefined)` question.
