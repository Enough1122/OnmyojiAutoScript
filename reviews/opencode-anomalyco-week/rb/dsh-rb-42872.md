1. packages/desktop/src/main/mods.ts (~fetch) — `oc-mod://` requests are authorized purely by URL hostname against the installed/enabled map, with no binding to the requesting webContents — any renderer that can reach the protocol (e.g. the main app window) can read every enabled MOD's assets regardless of its own permissions — tie served responses to the requester (verify an Origin/token header set at loadURL time) or serve MOD assets through the permission-checked IPC bridge instead of an unauthenticated protocol handler.
2. packages/desktop/src/main/ipc.ts (~mods-set-safe-mode..mods-open-window) — `mods-set-safe-mode`, `mods-reload`, `mods-preload`, `mods-set-enabled`, `mods-set-priority`, and `mods-open-window` never validate `event.sender` — today MOD windows expose only a narrow bridge, but any future preload regression would let a MOD window flip global loader state or spawn windows — add a cheap guard rejecting senders present in the manager's `windows` map (or asserting the sender is the main window).
3. packages/app/src/app.tsx (mods.safe-mode.enable) — the restart heuristic checks `mod.enabled && (contributes.server || contributes.database)` but omits the `compatible` filter that every sibling handler applies — an enabled-but-incompatible MOD can force a needless full app restart when entering safe mode — reuse the exact `mod.enabled && mod.compatible && (...)` predicate from `mods.safe-mode.disable`.
4. packages/desktop/src/main/mods.ts (reload) — `installed.clear()` followed by re-population runs while IPC readers execute concurrently, so a racing `list()`/`openWindow()` can observe a half-empty registry — build the new maps completely and swap them in a single synchronous step, or serialize reloads against reader entry points.
5. packages/desktop/src/main/ipc.ts (mods-storage-*/mod-storage-*) — storage and openExternal handling is duplicated in id-parameterized (`mods-storage-*`, `mods-open-external`) and sender-scoped (`mod-storage-*`, `mod-open-external`) variants — duplicated authorization checks drift apart over time, and the id-parameterized pair lets the main renderer address any enabled MOD's storage namespace — collapse into one sender-scoped implementation, with the explicit-id variant delegating to the same guards.
6. packages/desktop/src/main/sidecar.ts (prepareSidecarEnv) — MOD wiring reaches the sidecar via stringly-typed environment (`OPENCODE_DESKTOP_MOD_PLUGINS` JSON blob, `OPENCODE_DISABLE_CHANNEL_DB=1`) — undocumented env contracts break silently, and the channel-DB kill switch is all-or-nothing rather than routing the MOD at a copied database — document both variables as a stable contract in MODS.md, and prefer extending the typed StartCommand channel over env vars.
