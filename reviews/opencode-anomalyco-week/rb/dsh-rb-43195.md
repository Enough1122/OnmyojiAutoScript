Nice work overall — the transactional import (`db.transaction` wrapping session/message/part writes) is a real improvement over the old non-atomic writes, child ordering makes exports deterministic, and the docs are updated. A few concerns:

- `packages/opencode/src/cli/cmd/import.ts:177-180` (and `:270`) — Strict whole-file validation via `Schema.decodeUnknownExit(SessionTransferFile)` replaces the old lenient per-field decode, and the `time?.created ?? Date.now()` fallback is gone — legacy exports that previously imported (older schemas, missing `time`) now hard-fail with a raw parse error. The test comment at `packages/opencode/test/cli/session-transfer.test.ts:158` acknowledges this tradeoff, but no migration path ships. Suggestion: keep a lenient legacy branch (or version-detect the payload) and/or surface an actionable message like "re-export with a newer opencode" instead of a schema dump.

- `packages/opencode/src/cli/cmd/import.ts:251-263` — `onConflictDoUpdate` unconditionally repoints any existing session row whose ID collides with an archive entry to the importer's project/directory/path. Importing someone else's shared archive can silently re-home unrelated local sessions (their messages stay due to `onConflictDoNothing`, but ownership metadata is mutated). Suggestion: detect collisions where the existing row differs and require an explicit opt-in flag, or skip with a warning listing the affected IDs.

- `packages/opencode/src/cli/cmd/import.ts:232-245` — The strand check only inspects *direct children of moved* sessions, so an archive that includes a child but omits its parent passes validation: the child moves to the target project while its parent stays behind, splitting the tree across projects. `collectSessionTree` always emits complete subtrees, but hand-edited or partially trimmed archives validate fine. Suggestion: additionally require each included session's `parentID` to be either included in the archive or already resident in the target project.

- `packages/opencode/test/cli/session-transfer.test.ts:105-157` — Tests cover the deep round-trip and the legacy-rejection path (`:159-182`), but there is no test that a plain legacy `{info, messages}` single-session file still imports successfully through the new union decode. That's the main backward-compatibility contract of this change; suggestion: add a happy-path legacy import test asserting rows land in the target project.

- `packages/opencode/src/cli/cmd/import.ts:298` — Converting `SqlError` to a defect via `Effect.die` turns ordinary DB failures (locked database, constraint violation, disk full) into crashes with stack traces rather than a friendly CLI error. Suggestion: `fail` with a formatted message, consistent with the other import errors in this file.

- `packages/opencode/src/cli/cmd/export.ts:15-24` — Cycle/duplicate protection in `collectSessionTree` depends on `seen` being mutated between sibling visits, which only holds because `Effect.forEach` defaults to sequential concurrency; a future switch to concurrent traversal would silently reintroduce duplicate visits. Suggestion: add a comment documenting the sequential-traversal invariant (or dedupe after collection).
