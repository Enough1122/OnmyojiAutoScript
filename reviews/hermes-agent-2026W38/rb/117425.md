## Overview

This PR gives shutdown a disposition for boot auto-resumes that were *scheduled* but whose turn body never started. It adds `gateway/drain_resume.py` (pure predicate: `classify_boot_resume_at_shutdown`, `drain_admission_reason`), a per-session `_pending_boot_resumes` registry in `gateway/run_startup.py`, a cancel-and-re-mark pass invoked from `_stop_begin_teardown` before the drain wait (`gateway/run_shutdown.py:1745`), and a `PHASE=drain_admission` line at the turn chokepoint (`gateway/run_turn.py:2131`). The diagnosis holds against main: `_running_agent_count()` is `len(self._running_agents)` and therefore counts sentinels (`gateway/run.py:3953`) while `_snapshot_running_agents()` excludes them (`gateway/run.py:3983`), so the contradictory `active_at_start=0, active_now=5` is real; and the re-marked reason cannot be clobbered later in the same shutdown — `_mark_running_sessions_resume_pending` skips sentinel slots (`gateway/run_shutdown.py:865-867`) and the cancelled session has already left `_running_agents`, so it is not in `_pre_drain_keys` and escapes the `clear_resume_pending` pass (`gateway/run_shutdown.py:1822-1825`). All referenced symbols exist with the expected signatures (`suppress` already imported at `gateway/run_startup.py:17`, `_draining`, `mark_resume_pending(session_key, reason) -> bool`, `_pending_messages: Dict[str, MessageEvent]`, `entry.resume_reason`). The tests are hermetic and drive the real methods. One hazard in the cancel path is worth settling before this lands.

1. **The cancel path cancels the bookkeeping, not necessarily the turn.** `gateway/run_startup.py:151` cancels the wrapper task, then `:166` releases the slot and `:174` re-marks the session resumable. But the wrapper it cancels (`_run_startup_resume_event`; its `finally` branch is the diff context at `gateway/run_startup.py:64-69`) does `await adapter.handle_message(event)` and then `await asyncio.shield(<the adapter's per-session task>)`. `asyncio.shield` exists precisely so the inner task is *not* cancelled when the outer one is. If shutdown lands while the wrapper is parked there — `handle_message` has returned, the session task exists, the turn body is still waiting for a free worker on the shared executor, i.e. exactly the "scheduled but body not started" shape this PR targets — then the turn survives the cancel and runs anyway, the slot has already been released so the drain no longer tracks it, and the durable mark has been rewritten, so the next boot resumes the same session a second time. Net: a turn running during/after shutdown with an untracked slot plus a duplicate resume — the outcome the PR sets out to remove. Suggested fix: also cancel/neutralise the adapter's session task for that key (or skip the cancel-and-re-mark when `adapter._session_tasks[session_key]` is a live task), and re-read the slot immediately before releasing and re-marking so a turn that started during the awaits is not re-marked. Please confirm the wrapper can be parked at that shield when this runs; if it can, this is a blocker rather than a nit.

2. **The registration is cleared earlier than the state the cancel path keys on.** `gateway/run_turn.py:2134` drops the registration at chokepoint *entry*, while the cancel path's "turn never began" signal is the sentinel still occupying the slot (`gateway/drain_resume.py:82`). If `state.turn.agent` is promoted to the real agent later than that entry point — the PR's own incident description implies it is, since five turn bodies started 30s into the drain while `_snapshot_running_agents()` had returned zero non-sentinel agents — then a resume admitted into `_handle_message_with_agent` but not yet running has no registration at all: shutdown neither cancels it nor names it in `PHASE=drain_admission`, and the drain waits on the sentinel exactly as before. Please confirm the promotion point relative to `_handle_message_with_agent`; if it is after entry, the clear (or the classify input) should move to the promotion site, otherwise the fix covers only resumes that never reached the inbound handler.
