This PR makes ACP edit auto-approval evaluate every real target of a multi-file V4A patch instead of the comma-joined display string: `EditProposal` gains `paths: tuple[str, ...]`, `_proposal_for_patch_v4a` fills it from `_extract_v4a_patch_paths`, and `should_auto_approve_edit` now runs the sensitive-path check per path and requires `all(...)` paths to sit inside the temp or workspace root (`acp_adapter/edit_approval.py`). That closes the join-hiding hole it targets — the `.env` hidden behind a benign sibling no longer auto-approves under `session`/`workspace_session` — and the added tests cover the sensitive, escape and all-safe cases. One bypass survives, because the approval-side extractor is stricter than the executor's parser:

1. **BLOCKER — a V4A header spelled without a space after `***` is invisible to the check but still applied by the executor** — the approval extractor uses `_V4A_FILE_RE = re.compile(r'^\*\*\*\s+(?:Update|Add|Delete)\s+File:\s*(.+)$')` (`acp_adapter/edit_approval.py:45`, and `_V4A_MOVE_RE` at :46), i.e. `\s+` — one or more whitespace. The executor's parser uses `\*\*\*\s*Update\s+File:` (`tools/patch_parser.py:49-52`, the module imported by `tools/file_operations.py:1386 — from tools.patch_parser import parse_v4a_patch, apply_v4a_operations`), i.e. zero or more, and `tools/file_tools.py:145-147` states this explicitly: "``\s*`` after ``***`` mirrors patch_parser's leniency (``***Update File:`` applies, so it must be checked)". Repro, with a requester bound (ACP session) and policy `workspace_session` or `session`:
   ```
   *** Begin Patch
   *** Update File: src/ok.py
   @@
   +ok
   ***Update File: /Users/me/.ssh/authorized_keys
   @@
   +ssh-ed25519 AAAA...
   *** End Patch
   ```
   `_extract_v4a_patch_paths` (`:101`) sees only `src/ok.py`, so `paths` is `("src/ok.py",)`, `_is_sensitive_auto_approve_path` (`:138`) never sees the `.ssh` path, the workspace `all(...)` check passes, and `should_auto_approve_edit` returns `true` — the requester auto-approves (or shows a diff containing only the benign file) while `parse_v4a_patch` applies both hunks. This is exactly the "sensitive/escaped file hides" class the PR set out to close, so the fix is incomplete as shipped. Note the all-space-less variant is safe (`paths` comes back empty → `_proposal_for_patch_v4a` raises → `maybe_require_edit_approval` denies), which is why the mixed spelling is the exploitable form. Fix: make the approval-side patterns match the executor's (`\*\*\*\s*`), or better, parse the path list from the same `tools.patch_parser` helper the executor uses so the two can never drift.

Minor: `test_v4a_move_file_checks_both_endpoints` guards the assertion with `if proposal is not None:` — harmless today (`_V4A_MOVE_RE` does extract both endpoints and `paths` therefore carries source+destination), but the guard would silently turn the test into a no-op if the parser ever dropped move support; prefer asserting `proposal is not None` outright.
