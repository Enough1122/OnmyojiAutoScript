The one problem is that the new value is interpolated with `shq` alone.

1. **`HERMES_HOME` is shell-quoted with `shq`, so a `~/`-prefixed install root reaches the child as a literal tilde and the named-profile spawn fails** — blocker (narrow trigger, but a hard startup failure; one-line fix). `apps/desktop/electron/remote-lifecycle.ts:1104` defaults to `const installHome = opts.hermesHome || '~/.hermes'`, and `probeRemoteHermesHome` falls back to the same literal (`remote-lifecycle.ts:287`, `return out || '~/.hermes'`) whenever the remote `echo "${HERMES_HOME:-$HOME/.hermes}"` comes back empty. `resolveProfileHermesHome('~/.hermes', 'foo')` then yields `~/.hermes/profiles/foo`, and line 1109 interpolates it as `HERMES_HOME=${shq(spawnHome)}`. `shq` (`remote-lifecycle.ts:130-132`) is a plain single-quote wrapper (`'...'`), so the tilde is not expanded by the remote shell, and the child receives the literal string. With a named profile the child dies immediately: the CLI entry calls `resolve_profile_env` (`hermes_cli/main.py:608`), which builds `profile_dir` from the raw env value (`hermes_cli/profiles.py:2069-2075`) and guards it with `named_profile_is_live` → `Path(profile_home).is_dir()` with no `expanduser` (`hermes_constants.py:289-292`) → `FileNotFoundError` → "Error: ..." and `sys.exit(1)` (`main.py:611-613`), even though the real profile exists at `$HOME/.hermes/profiles/foo`. The default/empty profile is not affected (`get_hermes_home()` does expand the value: `hermes_constants.py:162-163` and `46-48`), and a successfully spawned backend still records the un-expanded literal in the lockfile, so the next connect with a non-empty probe sees a different `hermesHome` and respawns once. Before this PR the same fallback case worked, because no `HERMES_HOME` was exported at all. The module already has the right tool for this and uses it everywhere else: `expandRemotePath` (`remote-lifecycle.ts:154-165`) renders `~/x` as `"$HOME"` + `shq`-quoted remainder, and other `shq`-interpolated paths get an explicit remote-side `os.path.expanduser(...)` (`remote-lifecycle.ts:630`, `635`, `1240`). Fix: `HERMES_HOME=${expandRemotePath(spawnHome)}` (and keep the `shq` behavior for absolute paths unchanged, which that helper does).
