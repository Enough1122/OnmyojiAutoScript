1. **Post-mount `setLoading(true)` re-engages the chat-host gate and can kill the persistent PTY on every reload** — non-blocking
   - web/src/plugins/usePlugins.ts:126 — the refresh handler now raises `loading` after mount whenever any fetched manifest is not yet registered (`setLoading(list.length > 0 && !list.every(isManifestRegistered))`). Old code only ever lowered `loading` post-mount: the fetch handler only called `setLoading(false)`, and both the 2s timeout and `resolvePlugins` only lowered it, so it was monotonic after the initial seed.
   - App.tsx consumes this flag to gate the persistent embedded-chat host (`pluginsLoading ? fallback : <ChatPage/>`), an invariant its comments call load-bearing precisely to avoid "mount, spawn a PTY, and then get yanked out … killing the session mid-paint". With cached manifests the initial seed sets `loading=false` (`canSeedLoadedFromCache`), the chat host mounts, then the manifest fetch resolves — typically before the freshly injected plugin scripts finish executing — and sets `loading` back to true: the host unmounts, the PTY dies, and it remounts only when scripts register or at the 2s timeout.
   - Repro: embedded chat enabled, at least one plugin installed (none overriding `/chat`), reload while on `/chat`.
   - Suggested fix: keep post-mount transitions monotonic (only lower the flag once seeded), or derive the raise from scripts not yet activated this session rather than registry state — while still allowing a deliberate unmount when a fetched manifest newly declares `tab.override: "/chat"`.
