Overview: this PR adds message quoting to group-chat rooms — a `GroupQuote` snapshot type (`types.ts`), `quoteFromMessage()` in the new `group-quote.ts`, a Quote action on every log entry, a removable quote strip on the main composer, and the quoted reference rendered above the reply (`group-chat-view.tsx`); `replyTo` is threaded through `appendGroupChatEntry` / `sendToGroupChat` (`group-chat.ts`, `group-rounds.ts`). The main-composer path is clean and tested (new `group-quote.test.ts`, the `group-rounds.test.ts` case, and the render test). Two behavioural gaps, both in paths the tests do not exercise.

1. A quote armed while a thread reply box is open is silently dropped, and then leaks into the next main-composer send.
   - The Quote button is added to the shared entry action row (`group-chat-view.tsx:1175-1187`, inside `renderEntry`), so it is offered on any message — including while a thread's reply box is open (`group-chat-view.tsx:1267`, `key={replybox:${id}}`, `onSubmit` → `submitReply`).
   - `submitReply` still sends without the quote and never clears it: `sendToGroupChat(group, memberDescriptors(), text, thread, images)` at `group-chat-view.tsx:978`, and its cleared draft (`group-chat-view.tsx:964-975`, inside `submitReply` at `group-chat-view.tsx:954`) resets only `replies`/`pendingAttachments` — `quote` stays armed. The only quote strip is the main composer's (`group-chat-view.tsx:1386-1409`), so nothing next to the reply box shows the armed quote; only `submit()` clears it (`quote: null`, `group-chat-view.tsx:937`) and consumes it (`group-chat-view.tsx:943`).
   - Repro: open a thread → hover a message → Quote → type in the thread's reply box → send. The reply lands unquoted, the quote stays armed, and the next message sent from the main composer goes out carrying that stale quote.
   - Suggested fix: either consume `quote` in `submitReply` and render the strip in the reply box, or suppress the Quote action while a reply box owns the active composer, and clear `quote` on every send path.

2. `replyTo` never rides the ui_meta sync projection, which the new design comment says it does.
   - `groupChatSyncSnapshot` rebuilds each entry from an explicit field whitelist — `id`/`from`/`text`/`at`/`thread`/`truncated` (`group-chat.ts:316-345`) — and does not copy `replyTo`. That projection is what the profile ui_meta mirror (mobile / other desktops) reads, so a quoted reply shows up there without its quote line. Locally nothing is lost: the plugin-storage copy keeps `replyTo`, and the merge union prefers the local entry on a key tie (`group-chat.ts:539`).
   - This contradicts `group-quote.ts:10-12` ("the log is synced through profile ui_meta with a byte budget and a quote rides every member's copy of the message") — the stated reason for cutting the quote to `GROUP_QUOTE_TEXT_CHARS`.
   - Suggested fix: either copy a bounded `replyTo` into the projection (staying inside `GROUP_CHAT_SYNC_MAX_BYTES`), or correct the comment and accept that quotes are local-only.

Align the doc with the behaviour or pass `entry.at`.
