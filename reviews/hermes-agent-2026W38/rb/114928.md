`computer-use doctor` gains a machine-wide `cua-driver serve` daemon guard (`tools/computer_use/cua_daemon_health.py` + an additive seam in `doctor.py`), and the driver auto-repair stops reinstalling when the daemon is the broken half. Closing that detection gap is worthwhile; two details of the new diagnosis are wrong on host shapes the tests do not cover.

1. **`not_installed` loses to `not_running` whenever the unit names a path, so a driver-less host is told the binary is fine** — `tools/computer_use/cua_daemon_health.py:158` — `_freshness` tests "a reference's target is missing" (`cua_daemon_health.py:158`) *before* "no cua-driver is installed" (`:160`). A missing target requires `binary_is_path` (`cua_daemon_health.py:111-112`), so a unit written against a versioned `packages/releases/<version>/…` path on a host where the driver has been removed resolves to `not_running`, and the hint that ships with it (`:195`) reads "Reinstalling the driver will NOT fix this — the binary itself is fine" while pointing at `~/.cua-driver/packages/current/cua-driver`, which does not exist on that host either. The `not_installed` state — whose hint is the correct "Run: hermes computer-use install" — is only reachable when every path reference still exists. The test that claims to pin this distinction (`tests/tools/test_computer_use_daemon_liveness.py:140-143`) uses a bare-name `ExecStart` (`"cua-driver serve"`), where `binary_is_path` is false and `binary_exists` is unconditionally true, so it can never reach the `missing` branch and passes either way. Checking `resolve_cua_driver_cmd()` before the missing-target branch would make the uninstalled case win.

2. **`doctor` attributes a missing target to the wrong unit file when more than one serve reference exists** — `tools/computer_use/doctor.py:339` — the row text takes the file from `status['references'][0]['path']` but the binary from `missing[0]`, and `references[0]` is the first reference in glob order, not the one that is missing. With two units where only the second points at a pruned path, doctor prints "<healthy unit> starts the daemon from a path that does not exist: <broken binary>", so the operator is sent to edit the wrong file. `cua_driver_daemon_status` gets this right (`cua_daemon_health.py:192` uses `missing[0]['path']`); the doctor row should use the same source. The new test has a single unit, so it cannot catch this.
