## Finding

**Blocker — Reload bypasses recovery on the second failure.** The recovery page's Reload button is implemented as `location.replace(reloadUrl)` (`apps/desktop/electron/renderer-load-error-page.ts:63-65`). The new recovery handler is only attached to the initial `loadWindowUrl(...).catch(...)` (`apps/desktop/electron/main.ts:2012-2025`). When a session, browser, or instance window retries from the page, the resulting main-frame `did-fail-load` reaches the lifecycle listener in log-only mode (`apps/desktop/electron/window-renderer-lifecycle.ts:371-374`), so the window can become blank again without the visible page.

Suggested fix: route Reload through a main-process callback that reuses the recovery policy, enable an appropriate recovery owner for these windows, or add equivalent handling for navigation initiated by the recovery page. Add a regression test that clicks/replays Reload and then emits another failure.
