Two issues are worth fixing before merge; both are non-blocking.

1. `tools/file_tools_write_guards.py:516` — the `$TMPDIR` branch prefix-matches without a path separator, so the exemption is broader than "temp dir".
   Evidence: `if tmpdir and real.startswith(os.path.realpath(tmpdir)):` — no trailing-separator normalization, unlike line 513 which correctly uses the `/tmp/` form.
   Reproduced on this host by executing the function body verbatim: with `TMPDIR=D:/Hermes/tmpdir-probe`, `_temp_path_exempt("D:/Hermes/tmpdir-probe2/user-notes.md")` returns **True** — a sibling directory that merely shares the prefix is exempted from the never-read refusal. With `TMPDIR="/"` every path is exempt (`_temp_path_exempt("/etc/passwd")` → True; that one is still caught by `_check_sensitive_path`, but other user files would not be). On Linux the common `TMPDIR=/tmp` makes `/tmpfoo/...` exempt too.
   Risk: a guard whose stated scope is "world-writable scratch space" silently covers non-temp trees; the exemption is exactly what the blocker exists to withhold from user data.
   Fix: `root = os.path.realpath(tmpdir).rstrip("/")` (and require `root and root != "/"`), then `real.startswith(root + "/")` — mirroring the trailing-slash discipline used two lines above.

2. `tests/tools/test_write_guard_temp_exemption.py:26,30,38,42` (and the `tmp_path`-based positive test at `:80`) — hard-coded POSIX paths assume POSIX realpath semantics.
   Evidence: on win32 `os.path.realpath("/tmp/clawdtalk-report.txt")` → `'D:\tmp\clawdtalk-report.txt'` (verified on this Windows host), so `startswith("/tmp/")` / `startswith("/var/folders/")` are False and those five asserts fail. The file carries no marker or skipif, and `tests/conftest.py`'s `_OS_MARKS` block is explicit that a test needing host-specific semantics declares its OS rather than passing/failing by accident.
   Risk: the main lane is ubuntu-only (`.github/workflows/tests.yml:24`), so CI stays green — but anyone running the suite on Windows (Hermes ships a Windows desktop app) gets 5 failures from this one new file. macOS and Linux are fine; the `/private/*` dual-spelling handling is correct. The negative control at `:89` passes on Windows either way, so it will not catch this.
   Fix: `@pytest.mark.skipif(os.name == "nt", reason="POSIX realpath semantics")` on `TestTempPathExempt` and the two blocker tests, or build the asserted paths from `tmp_path` (the `$TMPDIR` test at `:46` already does this and is portable).
