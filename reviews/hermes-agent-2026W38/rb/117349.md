The desktop's other caller of this RPC on the same socket pool does the opposite for a status it does not know:

```ts
// apps/desktop/src/store/session-request-router.ts:95-97 (turnKeepsRunning)
  // Queued, redirected and future status values are non-terminal by default.
  // Releasing only an explicit terminal ACK avoids recreating client_gone

```

So if a route's backend answers `prompt.submit` with a status this build does not know — a newer hermes on a remote source; the enum has already grown to four values (`tui_gateway/contracts/prompt_voice.py:54-58`) — the verb throws *and* drops the hold that keeps the runtime attached, which is the `client_gone` cut this file exists to prevent. Keeping the hold whenever the reply carried any status (surfacing the unknown value) would match the router; keeping the current fail-closed release only for replies that carry no status at all is the narrower version of the same fix.
