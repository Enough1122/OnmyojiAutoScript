## Overview

This PR adds `hermes doctor --runtime` (single-request runtime-path diagnosis) and `hermes doctor --isolate` (clean-room cumulative profile slicing). The redaction and source-invariance handling look careful, and the tests pin the important contracts. Two non-blocking robustness/transparency issues below.

## Findings

1. **Per-slice billable inference requests are undisclosed (non-blocking)** — hermes_cli/doctor_isolate.py:260. `_default_probe` runs a full `run_runtime_diagnostic` (one live inference request) for the sterile control plus every cumulative slice, so `--isolate` can issue up to ~7 billable provider requests, while the `--runtime` help text promises "at most one minimal inference request" and the `--isolate` help text mentions no network activity at all. Consider stating the expected request count in the `--isolate` help/docs, or probing slices lazily (stop billing once a culprit is found is already the case — just disclose the worst case).

2. **Source-runtime resolution failure crashes `--isolate` with a traceback (non-blocking)** — hermes_cli/doctor_isolate.py:317. `runtime = runtime_override or _resolve_source_runtime(source_config)` runs outside any `_record_phase` wrapper, so a provider-resolution error (no credentials, unknown provider) propagates as an unhandled exception; the isolate branch in `run_doctor` also returns before the `warn_on_error` guard used by the static checks. Consider catching the failure and reporting `below_profile_layer` (or an `error_class`) instead of crashing.
