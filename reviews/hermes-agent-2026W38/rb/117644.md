> AI code review — automated follow-up for reference; not a maintainer.

This PR adds a third discovery class to Bedrock model discovery: Amazon Bedrock Marketplace endpoints. `_list_marketplace_model_endpoints` (agent/bedrock_adapter.py:1125) paginates `ListMarketplaceModelEndpoints`, keeps only `status == "REGISTERED"` entries that are `InService` per `GetMarketplaceModelEndpoint`, derives a provider label with the new `_extract_marketplace_provider` helper (agent/bedrock_adapter.py:1193), and the step is wired into the existing error-isolating loop (agent/bedrock_adapter.py:1182); tests cover the happy path and the AccessDenied path (tests/agent/test_bedrock_adapter.py:927, :955). I checked the field names/enums against the AWS API reference — `marketplaceModelEndpoints[].status` (`REGISTERED | INCOMPATIBLE_ENDPOINT`, optional) and `marketplaceModelEndpoint.endpointStatus` (e.g. `InService`) are correct, and the ARN ids survive the CLI picker's region filter (`bedrock_model_routable_from_region` returns True for ids without a geo prefix) and are used verbatim as the Converse `modelId`, which matches how Marketplace endpoints are invoked. Overall this is a clean, well-scoped addition that follows the existing inference-profile step; the items below are non-blocking.

1. **A single per-endpoint `GetMarketplaceModelEndpoint` failure aborts the whole Marketplace step and caches a partial list for an hour** — agent/bedrock_adapter.py:1147. The `get_marketplace_model_endpoint(...)` call has no per-endpoint error handling, so one `ThrottlingException` / `ResourceNotFoundException` / per-ARN `AccessDeniedException` mid-loop propagates to the step's `except` at agent/bedrock_adapter.py:1186 (logged at debug, :1187), which returns the models accumulated so far — endpoints after the failing one are silently dropped, and that partial list is written to `_discovery_cache` for the 1 h TTL (agent/bedrock_adapter.py:1160, write at :1189). A loop of N Get calls is a realistic place to get throttled, so the failure mode is "some endpoints disappear for an hour, no warning above debug level". Suggested fix: wrap the Get (and the append) in `try/except Exception: continue` so one bad endpoint only costs itself, and/or log the count of skipped endpoints.

2. **The derived provider label does not line up with `provider_filter` semantics** — agent/bedrock_adapter.py:1142, :1145, :1193-1199. For foundation models the filter matches `providerName` *or* the id prefix (agent/bedrock_adapter.py:1093), and the documented config knob is `bedrock.discovery.provider_filter` with examples like `["anthropic", "amazon"]` (hermes_cli/config_defaults.py:679). Marketplace entries instead get the first hyphen-delimited token of the SageMaker hub model name, which is the hub's spelling, not Bedrock's provider name — the PR's own test uses `Nvidia-Frontier` → `nvidia` (coincidentally equal), but hub names like `AI21Labs-Jurassic-2` / `StabilityAI-StableDiffusion` would yield `ai21labs` / `stabilityai` and be silently excluded by a filter of `["ai21"]` / `["stability"]`. Please confirm against the hub model names you expect to see, and consider matching on the endpoint/model name as well (as `_list_foundation_models` does with the id prefix), or documenting that Marketplace entries are filtered by the hub-derived token only. Related: when `modelSourceIdentifier` is missing or does not match `/Model/`, the label is `marketplace` (agent/bedrock_adapter.py:1197) and any non-empty filter drops the endpoint entirely — worth a comment if intended.

3. **Modality/streaming are asserted without evidence for Marketplace endpoints** — agent/bedrock_adapter.py:1153. `_model_entry(endpoint_arn, name, provider, ["TEXT"], ["TEXT"])` plus `"streaming": True` from `_model_entry` (agent/bedrock_adapter.py:1080-1082) means an image/embedding hub model registered as a Marketplace endpoint (Stability-style content is in the public hub) is advertised to the picker as a streaming text model and only fails at the first Converse call. The inference-profile path does the same, so this may be a deliberate assumption — if so, a one-line comment stating "Marketplace endpoints are assumed text+streaming" would make it reviewable.
