1. **Per-protocol `ProxyServer` values become malformed proxy URLs** (blocker) — `_detect_windows_system_proxy` splits `ProxyServer` on `";"` and takes the first entry, prefixing `http://` when no scheme is present. Windows stores per-protocol lists as `http=host:port;https=host:port;ftp=host:port;socks=host:port`, so the first entry becomes `http://http=host:port`. `normalize_proxy_url` (`utils.py`) does no validation and passes it through, so every proxied platform send fails to parse/resolve. Repro: `ProxyEnable=1`, `ProxyServer="http=10.0.0.1:8080;https=10.0.0.1:8080"`, `gateway.trust_env` on, no proxy env vars → `resolve_proxy_url` returns `http://http=10.0.0.1:8080`; before this PR the same host got `None` and connected directly, so this is a regression for those users. The code comment ("may store `host:port;host:port` (auto-detect)") describes a format Windows does not use. Fix: detect `key=value` entries and parse them (prefer `http`/`https`, then `socks`), treating only a bare `host:port` as the all-protocol form.
