Adds a pre-spawn guard for the kanban review lane (validates that the force-loaded
`sdlc-review` skill actually resolves under the assignee profile's home, blocking the card
instead of crash-looping) and re-anchors the crash-output extractor so a pre-boot crash
reports its own stanzas instead of the predecessor run's final chat. The overall direction is
right and the two behaviors are pinned by real tests (both new test cases are red on current
main by inspection). The findings below are about the guard's own failure modes: two of its
documented contracts do not hold in the implementation, and the extractor's new anchor is a
whole-log text search.

1. The "resolver fault keeps the legacy spawn" safety net is unreachable (non-blocking).
   `_review_skill_missing` wraps `_load_skill_payload("sdlc-review")` in
   `except Exception: ... return None` (`hermes_cli/kanban_db_dispatch.py:1873-1879`) so that a
   loader fault is supposed to fall through to the normal spawn. But `_load_skill_payload`
   already swallows every internal failure and returns `None`
   (`agent/skill_commands.py:170-176`: the import, `normalize_skill_lookup_name`, `skill_view`
   and the JSON decode are all inside one `try/except Exception: return None`). A crashed
   loader, an unreadable skill tree or a JSON decode failure is therefore indistinguishable
   from "skill absent", and the guard takes the block path: `_record_task_failure(...,
   force_trip=True)` (`hermes_cli/kanban_db_dispatch.py:2205-2213`) sets `sticky` + `gave_up`
   and blocks the card on the first claim with an "install sdlc-review" hint that is wrong.
   Since this path is the one the lane must never lose to its own diagnostics, either
   distinguish absent from broken (call `skill_view` directly and inspect the returned JSON
   `success`/error, e.g. "not found"/"disabled" vs anything else) or drop the claim in the
   comment. Fix is small; impact needs a loader fault to trigger, hence non-blocking.

2. Project-local skill dirs ARE consulted, contrary to the docstring (non-blocking).
   `_review_skill_missing`'s docstring says "Project-local skill dirs are deliberately not
   consulted: the child's cwd differs from this process's" (`hermes_cli/kanban_db_dispatch.py:
   1858-1862`), and the call-site comment claims the guard "blocks exactly what the worker
   would die on" (`hermes_cli/kanban_db_dispatch.py:2196-2204`). The validation goes through
   `_load_skill_payload` -> `skill_view`, whose search roots come from `_skill_search_dirs()`
   (`tools/skills_tool.py:172-180`, used at `tools/skills_tool.py:592-594`), which prepends
   `get_project_skills_dirs()` — cwd-derived and trust-gated (`agent/skill_utils.py:495-498`).
   The dispatcher's cwd is not the worker's cwd (workers spawn into the task workspace), so a
   trusted project-local `sdlc-review` can satisfy the guard while the child resolves nothing
   and dies pre-boot: a false pass that leaves the reported incident unfixed in exactly the
   repos that carry project-local skills. Either resolve only home + external dirs (walk the
   loaded skill's `skill_dir` returned by the loader and reject it when it is under a project
   root) or state the limitation instead of claiming exclusion.

3. Minor: the extractor's anchor is a whole-log text search. `messages_at = raw.rfind("Messages:")`
   (`hermes_cli/kanban_db_dispatch.py:1008`) assumes the last occurrence of that literal belongs
   to the exit summary. When the final run crashed AFTER printing its own chat (no summary of
   its own), and that chat contains a line with "Messages:" — including the incident class this
   PR investigates, where a worker prints log excerpts — the window starts mid-chat and the
   reported diagnostic is a tail fragment. Anchoring on the last exit-summary block as a unit
   (marker -> end of the `Messages:` line, taken from the last marker occurrence) would be
   immune.

4. Minor: the guard performs a full skill resolution inline in the dispatcher tick
   (`hermes_cli/kanban_db_dispatch.py:2205`), i.e. an uncached profile `config.yaml` parse plus
   a directory scan behind `skill_view`, on every review-lane claim. Accepted for correctness;
   worth a small TTL cache keyed by (profile home, dir signature) if review lanes get busy,
   since a claim now costs noticeably more than the skills-list append it replaced.
