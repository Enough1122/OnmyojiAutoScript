This PR adds a best-effort "native final-response fanout" for API-driven turns: `APIServerAdapter` gains a `set_final_response_fanout_handler` seam plus `_fanout_completed_api_turn` (`gateway/platforms/api_server.py`), both session-chat handlers call it on a completed turn, `GatewayRunner._deliver_api_final_response` (`gateway/run.py`) resolves the owning adapter via `_delivery_adapter_for` and sends through it, `_wire_adapter_handlers` (`gateway/run_adapters.py`) installs the handler, and a 279-line test file covers gating, non-blocking scheduling, and profile/transport-identity routing. The scheduling design (fire-and-forget task, exception swallowed, registered for shutdown drain, delivery must not delay the HTTP response) is sound and the test set is unusually thorough. However, as this diff stands the fanout is unreachable in production, and the completion gate diverges from the canonical turn-finished predicate used everywhere else in the gateway.

2. **Non-blocking, but fix before landing — the completion gate omits `interrupted` (and `error`), unlike every canonical predicate in the tree.** The new gate is `result.get("completed", True) and not result.get("failed") and not result.get("partial")` (`gateway/platforms/api_server.py:3256` and `:3326`). The three existing "this turn really finished" predicates all include the interrupt flag: `gateway/platforms/api_server_runs.py` `terminal_run_status` (`not interrupted and not result.get("failed") and not result.get("partial") and result.get("completed") is not False`), `gateway/run_turn_runner.py:1739-1742` (`not result.get("failed") and not result.get("interrupted") and result.get("completed") is not False`), and `gateway/run.py:3183-3186` (also checks `error`). Because `completed` is treated as "not False" (not "is True"), a result carrying `interrupted: True` with `completed` absent/`None` passes this gate; the native chat would then receive the interrupt **diagnostic** `final_response`, which is precisely what `gateway/run_turn_runner.py:1735-1738` warns against adopting ("interrupt paths return {interrupted: True, completed: False} with a DIAGNOSTIC final_response"). The PR's own test only covers the `{"completed": False, "interrupted": True}` shape, so it does not pin the `completed`-absent case. Suggested fix: reuse the existing helper instead of hand-rolling the gate — `gateway/platforms/api_server_openai_routes.py:60-65` `_result_flags()` already returns `(completed, partial, failed, error)`, and `api_server_runs.terminal_run_status` is the shared terminal-status mapping.
