1. **Blocker — the forbidden-token filter is case-sensitive, so a mixed-case token passes it and the browser honours it.** apps/desktop/src/components/ui/sandboxed-frame.tsx:32 (`.filter(token => token && !FORBIDDEN_SANDBOX_TOKENS.has(token))`, blocklist at :15). HTML defines the attribute value as "an unordered set of unique space-separated tokens that are ASCII case-insensitive" (https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox), and Chromium lowercases each token before matching it — services/network/public/cpp/web_sandbox_flags.cc, `ParseWebSandboxToken`: `std::string lowered_token = base::ToLowerASCII(token);` then a lookup of `"allow-same-origin"` / `"allow-top-navigation"` etc. So `<SandboxedFrame sandbox="allow-scripts ALLOW-SAME-ORIGIN ALLOW-TOP-NAVIGATION" src=... title=.../>` renders `sandbox="allow-scripts ALLOW-SAME-ORIGIN ALLOW-TOP-NAVIGATION"` verbatim: the frame is no longer opaque-origin, and `allow-top-navigation` lets the guest navigate the host window — exactly the class of escape the file's own docstring says it refuses "whatever the caller asks". The threat model is a caller who wants a forbidden token, which is the case this filter exists for. Fix: normalise before the membership test, e.g. `.map(token => token.trim().toLowerCase()).filter(token => token && !FORBIDDEN_SANDBOX_TOKENS.has(token))`, and pin it in sandboxed-frame.test.tsx (`sanitizeFrameSandbox('ALLOW-SAME-ORIGIN allow-scripts') === 'allow-scripts'`). A positive allowlist of safe tokens would be more durable than a blocklist (unknown tokens are currently forwarded; Chromium ignores them but logs "is an invalid sandbox flag").

2. **Non-blocking — the trailing spread re-opens the attributes that carry the privacy posture.** apps/desktop/src/components/ui/sandboxed-frame.tsx:58-63: `loading="lazy"` (:58) and `referrerPolicy="no-referrer"` (:59) are set before `{...props}` (:63), and both stay in `SandboxedFrameProps` because only `src` is `Omit`ted and only `className`/`sandbox`/`src`/`title` are destructured. `<SandboxedFrame referrerPolicy="unsafe-url" loading="eager" src=... title=.../>` type-checks and wins over the defaults, so the documented "no-referrer" guarantee is not actually enforced by the primitive.
