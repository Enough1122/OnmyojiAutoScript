This plugin adds a pre-compaction persistence hook, but its default storage and commit behavior are tied to one author's machine and can mutate the wrong Git repository. That is unsafe for a bundled context-engine plugin.

1. **The default path is not portable and can create a relative `F:` tree in the active workspace** — `plugins/context_engine/persist_before_compress/__init__.py:40-52`, `:105-115`, `:214-225`.

   When `MEMORY_DIR`/`MEMORY_STORE` are unset, the plugin hard-codes `F:/hermes working directory/memory`. On POSIX systems that string is not an absolute path (it is interpreted relative to the process cwd), so a normal compaction can create `F:/hermes working directory/memory` beneath the user's working directory and write the snapshot there; on Windows installations without an `F:` volume it instead silently fails. The plugin should resolve storage from the supported Hermes memory/configuration paths (or require an explicit configured path and fail closed), rather than baking in a machine-specific drive.

2. **Automatic compaction stages and commits unrelated changes in the memory repository** — `plugins/context_engine/persist_before_compress/__init__.py:143-160`.

   `_commit_dictionary()` runs `git add -A` in `MEMORY_DIR`, so any pre-existing user edits or other untracked files in that repository are included in the automatic `persist_before_compress` commit, not just `learnings.jsonl`/`index.json`. This can unexpectedly publish or commit work the user did not ask Hermes to touch. Please stage only the two owned files (or make committing opt-in), and add a test with an unrelated dirty file.
