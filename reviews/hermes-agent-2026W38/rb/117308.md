### 1. `null` overwrites the cached session the test says it protects — `apps/desktop/src/plugins/hermes-bots/data.ts:676`

The overlay guard is `hasOwnProperty(remote, field) && value !== undefined`, but the remote `profiles.list` emits these fields as **`null`**, not absent: `_profile_session_fields` (`tui_gateway/methods_profiles.py:216-227`) assigns `last_session`/`worker_session`/`canonical_session` on every row, and its docstring states "no/unreadable DB -> every field None (the readers swallow)". A JSON `null` is a present key, so the guard lets it through and `{ ...row, ...sessionFields }` blanks the row's cached `canonical_session`/`last_session`.

Reproduced against the post-image function (extracted, transpiled with esbuild, run in node): with `canonical_session: undefined` the cached `{ id: 'cached-chat' }` survives (the new test's case), while with `canonical_session: null` all three fields come back `null`. Effect: a transiently missing/unreadable remote `state.db` turns a previously hydrated Bot Chat back into the draft this PR exists to remove, for that poll.

Suggested fix: treat `null` like `undefined` in the overlay (`value != null`), or state explicitly that `null` is authoritative and pin that by adding the null case to `apps/desktop/src/plugins/hermes-bots/data.remote-sessions.test.ts:47-62`.
