2. **On `RENDERER_WALL_HOSTS`, a curl *failure* is indistinguishable from a wall and now permanently suppresses tier 2 — including for the published Docs/Sites the PR intends to keep fetchable.** `main.ts:5969` (spawn error) and `main.ts:5972` (no bytes: `--max-time 5` timeout, blocked proxy, empty error body) both resolve `{ authWall: false, title: '' }`; `link-title-wall.ts:75` then refuses the renderer for any listed host and the empty result is cached by the `.then(clean => cacheTitle(key, clean))` at `main.ts:6121-6122`. Before this PR the empty curl value still escalated, so a published Doc/Site (readable without cookies, as the comment at `link-title-wall.ts:15-17` notes) would resolve its title via the renderer. The trade-off is real — for a genuinely private link the renderer would load the wall — so please confirm this is intended; if not, carry a `failed`/`no-body` flag out of `fetchHtmlTitleWithCurl` and let tier 2 try only when curl could not fetch at all, or at minimum avoid caching the empty result.
