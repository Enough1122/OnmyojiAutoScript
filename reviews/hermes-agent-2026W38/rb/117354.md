Letting group turns end on a bare silence marker while keeping the DM fallback is a defensible reading of the documented contract (`website/docs/user-guide/messaging/index.md:133-145`: silence tokens are supported "For group chats, hooks, and automation flows", and the marker is still stored in the transcript), and routing both sites through one helper is the right shape — `gateway/run_turn.py:1529` and `:3693` are the only two places where the machinery check gates silence (`git grep is_machinery_display_kind` / `_UNEXPECTED_SILENCE_REPLY`). `turn_ctx.source` is a real `TurnContext` field (`gateway/turn_context.py:17`), so the second call site can't `AttributeError`, and `getattr(..., "chat_type", None)` also tolerates a `None` source.

One substantive gap, reproduced locally on `upstream/main` + this patch.

**1. The predicate covers only `chat_type == "group"`, so channel / thread / forum chats keep the old fallback (non-blocking)**

`gateway/run_turn.py:97`:

```python
return is_machinery_display_kind(display_kind) or getattr(source, "chat_type", None) == "group"
```

`"group"` is not the codebase's notion of a group chat. The canonical set lives at `gateway/authz_mixin.py:26` — `_GROUP_CHAT_TYPES = frozenset({"group", "forum", "channel"})`, used for `is_group` at `:638` — and adapters emit the other members: `"thread"` (`plugins/platforms/discord/adapter.py:6010-6011` — a guild text channel is `"group"` at `:6013-6014`, a thread is `"thread"`; same split at `:1531`), `"channel"` (`plugins/platforms/telegram/adapter.py:6762`, `:5342`; `plugins/platforms/discord/adapter.py:4222`, `:4227`; `plugins/platforms/mattermost/adapter.py:41`, `:583` — public channels default to `"channel"`; `plugins/platforms/teams/adapter.py:312`; `gateway/run_voice.py:235`), `"room"` (`plugins/platforms/matrix/adapter.py:2667`), `"forum"` (`plugins/platforms/feishu/adapter.py:3195`). `gateway/session.py:71` documents the four values as `"dm", "group", "channel", "thread"`, and `gateway/run_topics.py:325` already treats `("group", "channel")` as one group-like lane.

**2. Ambient side conversation vs. an addressed group message (design question, not verified as a defect)**

The docstring justifies the allowance with "silence is a normal response to side conversation", but this predicate cannot tell side conversation from a group turn that explicitly addressed the bot (an @-mention or owner command), so those turns now lose the fallback as well. The repo does draw that line elsewhere: `gateway/platforms/yuanbao.py:1105` (`if ctx.chat_type == "group" and not ctx.owner_command and not self._is_at_bot(...)`) observes ambient group traffic instead of answering it. No equivalent "addressed to the bot" signal reaches this function today, so I'm raising it as a question rather than a defect — flagging it so the trade-off is deliberate.
