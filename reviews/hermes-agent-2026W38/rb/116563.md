## Overview

This PR bounds the work a single message's `@`-references can force: a 16-ref expansion cap, a stat-based pre-read size refusal, prefix-only binary sniffing, streaming folder line counts, and a 4 MiB ceiling on `git`/`rg` helper output. The direction is right and most of the bounds are real. However, the ranged-file path does not deliver its headline guarantee (blocker below), and the new test pins the wrong half of the behavior.

## Findings

1. **Blocker — single-line giants are still materialized in full before the budget check.** `agent/context_references.py:310` (`_next_line`) loops `fh.readline(line_cap)` and appends every piece to `pieces` (line 318) until a newline or EOF, returning the complete line; only afterwards does the caller add `len(line)` to `total_chars` and compare against `char_budget` (lines 332–333). The per-`readline` cap bounds each syscall, not the total, so `@file:huge.json:1-1` on a GB-scale single-line file (minified JSON, one-line logs — the exact case the comment at lines 305–306 claims is safe: "cannot force an unbounded string into memory") still builds the whole line in memory before the oversized fallback triggers. Fix: thread the remaining budget into `_next_line`, stop collecting once it is exceeded, and return the oversized block without joining the full line. The same applies to the `:start-end` window loop, which can accumulate several giant lines before checking.

## Minor

- `test_line_range_bounds_reads_on_single_line_file` asserts each `readline` size is bounded but never asserts total memory read, so it passes despite the finding above; extend it to cap cumulative bytes (the counting hook already exists) once `_next_line` aborts early.
- In `_run_quiet`, if the child writes past the cap and exits in the gap between the over-cap read and `proc.kill()`, `kill()` raises `ProcessLookupError` inside the drain thread (uncaught thread traceback) and the caller sees returncode 0 with silently truncated stdout, which downstream treats as a complete `git diff`/`rg --files` listing. Guard the kill with a liveness check (`proc.poll() is None`) and treat a truncated-but-zero-status result as a fallback trigger. Very narrow race; cosmetic in practice.
