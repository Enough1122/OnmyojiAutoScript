## Overview

This PR reworks the #116535 shutdown accounting from a handler-side count to a worker-owned lease with an explicit adopt/release handoff (`turn_lease`), so a cancelled handler cannot release the shutdown count while the executor thread still runs, and it fixes the Windows wizard double-start/UAC re-prompt issue (#116550) by making `install()` own the start decision. The lease protocol was checked carefully: enter-then-release ordering keeps the handler+worker sum positive for a live turn, the `handler_holds` flag is always mutated under `_api_worker_lock` so exactly one side releases, and the `/v1/runs` path balances its lease even if `_profile_scope` entry raises. No blockers; two non-blocking notes below.

## Findings (non-blocking)

1. **`ServiceManager.install` coerces every backend's return to `bool`** — hermes_cli/service_manager.py:197. The wrapper `return bool(self._backend_module().install(...))` means the launchd/systemd backends, which still return `None`, now report `False` ("nothing installed here") even on success. No caller reads the value today, so nothing breaks, but the return contract is misleading for the next caller that does. Consider typing the wrapper honestly (e.g. `Optional[bool]`) or updating the other backends to return `True` on success. Non-blocking.

2. **Two unrelated fixes share one PR** — the #116535 worker-lease rework (gateway/platforms/api_server.py:1232, gateway/platforms/api_server_runs.py, gateway/run_shutdown.py) and the #116550 Windows installer change (hermes_cli/gateway_windows.py, hermes_cli/gateway.py) have no dependency on each other. ## Minor

- `_exit_api_worker` clamps at zero, which silently masks a double-release if one is ever introduced; acceptable defensively, but an assertion/log on unexpected underflow would surface protocol bugs earlier.
- The adopt protocol still has the inherent queued-but-not-started window (handler released after cancellation, worker thread not yet entered `_adopt_api_worker` at gateway/platforms/api_server.py:1259): a shutdown snapshot in that gap observes zero while a thread is technically alive. It cannot touch `state.db` before lease entry, and the executor quiesce joins queued work first, so this is not actionable — noted only for completeness.
