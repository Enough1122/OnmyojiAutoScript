## Non-blocking

### 1. `ignore_errors=True` no longer means "keep deleting past failures" — `utils.py:251-260` (with `:249`, `:237`)

The docstring promises the wrapper keeps `shutil.rmtree`'s semantics "and `ignore_errors`", but the flag is
only consulted *after* `rmtree` has already aborted: when the retry in `_on_error` cannot fix the entry
(`func(fpath)`, `utils.py:249`) it re-raises, which unwinds the traversal, and the outer `except OSError`
(`utils.py:256`) then swallows the error. Stdlib `shutil.rmtree(..., ignore_errors=True)` instead skips the
failing entry and keeps deleting the rest of the tree.

Reproduced on Windows with a file held open (`WinError 32` ⇒ `PermissionError` that chmod cannot fix —
same class as any locked file), root containing `01_ok, 02_ok, 03_locked, 04_ok`:

```
shutil.rmtree(root, ignore_errors=True)    -> leftovers ['03_locked.txt']
rmtree_readonly(root, ignore_errors=True)  -> leftovers ['03_locked.txt', '04_ok.txt']
```

`plugins_cmd.py:982` (`rmtree_readonly(staging, ignore_errors=True)` in the metadata-rollback path) is the
caller that wants best-effort cleanup, so it now leaves more behind than the call it replaced.

Fix: swallow the retry failure when `ignore_errors` is set, e.g.

```python
        try:
            func(fpath)
        except OSError:
            if not ignore_errors:
                raise
```

(Passing `ignore_errors=True` down to `shutil.rmtree` is not equivalent: shutil then replaces the hook
with a no-op and the read-only retry never runs.)

## Minor

### 2. The chmod retry can touch a symlink's target outside the tree — `utils.py:245-248`

`os.chmod(candidate, ...)` follows symlinks by default and the loop chmods `fpath` as well as its parent.
On POSIX, when the failing entry is a symlink inside a read-only directory (the exact shape this PR
targets), the parent chmod is what fixes the unlink — but the `fpath` chmod lands on the link *target*,
possibly a file outside the tree, and sets `+w`/`+x` on it. Cheap guard: skip when
`os.path.islink(candidate)` (or `follow_symlinks=False` where supported). Suggest confirming on POSIX —
only Windows was available to test here.

### 3. Same pattern left unconverted: `hermes_cli/profile_distribution.py:253`

`shutil.rmtree(staged / ".git", ignore_errors=True)` runs right after a shallow clone, i.e. on a tree with
exactly the read-only loose objects this PR is about, and `ignore_errors` makes the failure silent — the
"(`.git` removed)" contract of `_stage_source` is not met on Windows. Impact is limited (the staged tree
lives in a `TemporaryDirectory`, whose own cleanup retries permission errors), but `rmtree_readonly` is the
tool that was just added for this.
