This PR adds a "deliver-then-hold" path to the group-chat engine: when a sticky `stop @member` hold swallows a member's delta, the skipped entries are parked on the hold stamp (`pendingDelta`, `apps/desktop/src/plugins/hermes-bots/group-chat.ts:1640-1646`), moved onto the room at release (`group-rounds.ts:887-895`) and replayed into the member's next prompt (`group-round-members.ts:107-126`), with a new `heldBack` map added to `GroupChat` (`types.ts:192-195`) and to `updateGroupChat`'s inline durable map (`group-chat.ts:1608`). The core idea is sound and the two new tests (`group-rounds.test.ts:1250`, `:1278`) pin the happy path. However, the same diff also deletes `externalCursors` from the `GroupChat` type and from every persistence site without touching the files that still use it, which leaves the tree non-compiling; and the new `heldBack` state is persisted on one path only. Both need to be resolved before merge.

2. **Blocker — `heldBack` is written on one persistence path and read on none, so a restart or sync merge in the release→delivery window still loses the swallowed text.** The parked entries are moved off the hold stamp at release (`group-rounds.ts:889-895`) — after that they exist only in the live room object — and `heldBack` is added to `updateGroupChat`'s inline durable map (`group-chat.ts:1608`) but not to `durableGroupChatRooms` (`group-chat.ts:893-911`, where the removed `externalCursors` line used to be) nor to `mergeRemoteGroupChatSnapshotIntoRooms` (`group-chat.ts:812-816`), and `plugin.tsx`'s hydrate literal (around `:262-283`) does not rehydrate it. `persistGroupChatRooms` (`group-chat.ts:917-925`) writes exactly `durableGroupChatRooms` to storage, so a full persist on that path drops the map while `watermarks` (already advanced past the parked entries by `heldMemberWatermarkAdvance`, `group-round-members.ts:31-33`) are kept. Repro: hold `@research`, release it, restart the window (or let the remote-sync merge run) before that member's next committed turn — the parked entries are gone and, unlike the pre-fix state, no hold stamp is left to recover them from. Suggest adding `heldBack: room.heldBack || {}` beside `holds:` in `durableGroupChatRooms` and rehydrating it in `plugin.tsx` with the same object guard the other maps use.

3. **Non-blocking — `heldBack` is keyed by member only, so parked entries cross thread boundaries.** Watermarks are keyed `` `${thread}::${memberKey}` `` (`group-round-members.ts:44`), but the park/transfer/drain paths use the bare `memberKey` (`group-round-members.ts:79-82`, `group-rounds.ts:887-895`, `group-round-members.ts:107-113`), and the parked entries were captured after a `groupThreadOf(e) === thread` filter (`group-round-members.ts:48`) that is not re-applied at drain time (`deltaWithHeld` at `:113` bypasses it). A member held in thread A, released by a mention in thread B, receives thread A's parked entries inside thread B's prompt — the same isolation the file's own comment ("the member's turn sees only the conversation it's part of") is designed to keep. Suggest keying `heldBack` by `markKey`, or filtering `parked` by `groupThreadOf(e) === thread` at drain time.

4. **Non-blocking — the deleted `authoredByMember` watermark walk is replaced by a narrower check; please confirm the echo suppression it provided is fully covered.** The old post-reply walk stepped the watermark over every member-authored entry until the next user entry; the new code only advances when the watermark sits exactly one behind the log tail (`group-round-members.ts:270-276`, `if (r.watermarks[markKey] === r.log.length - 1)`). When any other entry (a mirrored own row from a concurrent sweep, a user row) lands between the anchor and the reply, the watermark stays behind the member's own reply and the member's next prompt contains its own text back as room news. `mirrorExternalGroupWrites` has its own guard (`group-external-writes.ts:178-183`) so this may be harmless in practice — but the walk removal is outside the PR's stated scope and no new test covers it; please confirm or restore the walk.
