## Findings

The current head fixes the earlier shorthand sweep issues, but `config_fingerprint()` still normalizes the top-level `tools` container without applying the scalar-aware semantics used by runtime matching inside the canonical dict. It calls `sorted(tools_filter.get("include") or [])`, so scalar `include: "ab"` is sorted character-by-character and collides with the distinct `include: ["a", "b"]` filter. The same applies to scalar `exclude`; numeric values also raise `TypeError` in the cache path. The posted follow-up requests reusing the runtime scalar-aware normalization and adding scalar-vs-list fingerprint/cache regression coverage.
