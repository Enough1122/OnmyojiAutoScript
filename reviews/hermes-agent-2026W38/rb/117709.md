This PR gives Bot Mode chats a per-row avatar: `assistant-message.tsx` renders a bot chat's assistant row as a two-column flex row (face gutter + content column, `flex-row items-start gap-2`), and the new `bot-chat-avatar.tsx` gates that on `isBotChatSession`, derives the profile handle from the bot owner key, and resolves the image through the shared `resolveAgentAvatar`/`agentAvatarCache` helper with a 🤖 fallback. The layout merge is sound (`cn` is `twMerge(clsx(...))`, so `flex-col`/`flex-row` and `gap-0`/`gap-2` resolve in the intended order), the hook calls `useStore` before its early return (rules of hooks hold), and the new tests cover handle parsing plus both avatar/fallback branches. Two non-blocking functional gaps are worth confirming before merge.

1. (non-blocking) A bot chat restored after a relaunch shows no face. The hook reads the owner key only from `$botChatScopes` (bot-chat-avatar.tsx:39), which is window-local and never persisted; after a restart `isBotChatSession()` is true again (its `$botChatSessionIds` set is restored from localStorage) but `scopes[stored]` is `undefined`, so `botChatHandle(null)` → `null` → no avatar until the chat is re-opened from the roster. Repro: open a bot chat, restart the desktop, look at the thread — the gutter is gone. Fix: fall back to the tile's persisted `workspaceOwnerKey` for tiled bot chats (`$sessionTiles`), and/or persist the owner key alongside the id set.

2. (non-blocking) Only the local connection id is stripped from the owner key (bot-chat-avatar.tsx:24, `.replace(/^local::/, '')`), but owner keys are `bot:<connectionId>::<profile>` (`botWorkspaceOwnerKey` / `botRouteKey` in the hermes-bots plugin). A bot on a remote connection yields `homelab::researcher`, which can never match a profile name in `resolveAgentAvatar`'s `p.name.toLowerCase() === key` lookup, so remote bot chats always fall back to the glyph — and the lookup runs on the active gateway, not the bot's owning connection. Please confirm this is intended; if not, strip any `<connectionId>::` prefix (or resolve through the bot's owning connection) rather than only `local::`.
