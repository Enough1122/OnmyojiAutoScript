No blockers; two robustness notes below.

1. **Dedup key collapses when create_at is absent** (non-blocking) — plugins/platforms/mattermost/adapter.py:657. `event_ts = str(reaction.get("create_at") or "")` means two distinct same-emoji reactions on the same post by the same user both missing `create_at` share one dedup key, so the second is silently dropped (no hook, no routing). Risk is low since Mattermost normally sends `create_at`, but a defensive fix is cheap: only treat the key as a duplicate when the timestamp is present, or mix in a per-delivery nonce. Fix at the `is_duplicate` call site.

2. **Allowlist match is case-asymmetric** (non-blocking) — plugins/platforms/mattermost/adapter.py:675. `_reaction_triggers()` lowercases configured names, but the event side compares `emoji_name.strip(":")` verbatim, so a non-lowercase server-side name would never match a normalized config entry. Mattermost normalizes emoji names to lowercase server-side, so this is largely theoretical. Fix: compare `emoji_name.strip(":").lower()` against the trigger set.

Minor: the hook payload always sends empty `item_user_id`/`team_id` for Mattermost — this is already disclosed in the hooks.md note added by this PR, so no action needed; flagging only in case hook consumers assume parity with Slack.
