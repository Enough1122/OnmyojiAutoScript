## Overview

The fix adds `_stale_pids()` (`hermes_cli/dashboard_procs.py:549-562`), which probes the callee's signature and, for an old-shaped callee, re-applies the same home filter locally through `_pids_owned_by_hermes_home` rather than silently dropping the scope.

Every other `_dash.*` attribute this function calls exists in that old generation too, so the finder really was the only drifted shape in this path. No blocking problem; the defects are in the new test file plus one hardening nit.

## Findings

1. `tests/hermes_cli/test_stale_dashboard_pid_signature_compat.py:115-121` — `test_new_shaped_finder_receives_scope_home` does not test a new-shaped finder. 2. `hermes_cli/dashboard_procs.py:558` — `inspect.signature(...)` is the one call in this helper that can itself raise: `ValueError`/`TypeError` for a callee it cannot introspect (C-implemented callables, callable objects without `__signature__`/`__wrapped__`), which would abort the sweep with exactly the "Could not refresh running dashboard/serve process(es)" outcome the helper exists to prevent. In-tree this is theoretical — the callee is a plain Python function, and the known doubles are lambdas / `mock.Mock` (verified: `inspect.signature(mock.Mock())` returns `(*args, **kwargs)`, so the `VAR_KEYWORD` branch already covers `mock.patch.object(main_dashboard, "_find_stale_dashboard_pids", return_value=...)` at `tests/hermes_cli/test_stale_pid_guard.py:182`). Cheap hardening: `try: params = inspect.signature(...).parameters except (TypeError, ValueError): params = {}` — falling back to the old-shaped path (local home filter) is the safe direction.
