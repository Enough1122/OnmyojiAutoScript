On main, `stop()` is marker → bounded drain → `schtasks /End` → force-kill (`hermes_cli/gateway_windows.py:1651-1687`). A successful drain exits 0 and the supervisor exits with it, so the clean path is fine; but when the drain times out — the documented reason the force-kill exists — one of two things happens, and neither matches the contract: if `schtasks /End` terminates the task's whole process tree, the gateway is hard-killed with the drain never completing (the marker promise in that docstring is void); if it only ends `wscript.exe`, the supervisor outlives the stop and, 5 s later, restarts the force-killed gateway as "crash recovery" — the user sees "✓ Gateway stopped" and the bot comes back, and `restart()`'s `_wait_for_gateway_absent` (`hermes_cli/gateway_windows.py:1689`) would then fail with "Gateway process still detected after force kill".
