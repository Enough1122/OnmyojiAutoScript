This PR makes memory-entry lookup tolerant of quote style and whitespace: it adds `_normalize_for_match` (`tools/memory_tool_store.py:62-73`), which collapses all single/double/curly quote variants to `'` and collapses whitespace, and adds a normalized fallback inside `_find_unique_match` (`tools/memory_tool_store.py:76-91`) that runs only when no entry byte-contains `old_text`. Two tests accompany it (`tests/tools/test_memory_tool.py:209`, `:217`). The core design is sound and conservative: exact matches still win (`tools/memory_tool_store.py:83`), the fallback cannot change any case that matched before, and the pre-existing ambiguity guard at line 89 is evaluated on raw entries, so two entries that are distinct on disk but identical after normalization are still reported as ambiguous. I also confirmed the whole-entry replacement in `_edit` (`tools/memory_tool_store.py:327`) means a tolerant match cannot produce a silent "Entry replaced." no-op — the new test and a direct run of the helper both show the entry text is actually swapped. The one real defect is in the error path that this PR newly reaches; the rest are minor.

1. The "multiple entries matched" error lists nothing when the ambiguity comes from the new fallback — `tools/memory_tool_store.py:322` (post-image; outside the diff hunk, but reached by the new code path).

The fallback at `tools/memory_tool_store.py:84-88` runs *only* when no entry byte-contains `old_text`, so whenever the fallback is what produced `ambiguous=True`, that list is empty and the tool returns `{"success": false, "error": "Multiple entries matched '...'.    - Risk: the caller here is the memory tool's LLM. It is told several entries matched but shown none, so it has nothing to refine `old_text` against and will most likely retry the same text — the opposite of the error's stated purpose.
   - Fix: reuse the needle, e.g. compute `needle = _normalize_for_match(old_text)` in `_edit` and use `if old_text in e or needle in _normalize_for_match(e)` for the listing (or fall back to `entries` when the exact filter is empty).

2. Quote-only needles pass the `if needle:` guard — `tools/memory_tool_store.py:85-88`.
   - The guard only checks truthiness, but normalization maps every quote variant to `'`, so an `old_text` of `"`, `'` or `“` normalizes to a single `'`, which is contained in any entry that uses any quote character.
   - Verified with the patched helper: entries `["alpha 'x' beta", 'alpha "y" beta']` with `old_text = "“"` → `(None, True)` (spurious ambiguity from a one-character `old_text`); with a single quoted entry the same needle matches that entry instead of failing.
   - Risk is low — exact matching has precedence and real `old_text` values are phrases, not bare quotes — but the guard is one line: e.g. `if needle and needle.strip("'")`, or require at least one non-quote character in the needle.

3. `remove()` and `apply_batch()` inherit the loosened matching, with no test coverage — `tools/memory_tool_store.py:310-313`, `:354`.
