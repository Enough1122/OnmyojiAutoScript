Strong security tooling: fail-closed on incomplete analysis, atomic baseline writes with fsync, symlink refusal, schema versioning, application-owned baseline wired into write-denied paths (with a test proving it), and 350+ lines of behavior tests. A few gaps:

- hermes_cli/security_config_scan.py (_parse_tirith_output) — Severity is uppercased but never stripped, so tirith emitting " high" or "high\n" classifies as unknown severity. Why it matters: unknown severities sort below INFO and can never trip the --fail-on gate (SEVERITY_ORDER.get(..., -1)), so a real CRITICAL with stray whitespace silently exits 0. Suggestion: .strip() before .upper(), and treat unrecognized severities as at least MEDIUM for gating (or surface them as a distinct warning count).

- agent/file_safety.py:62-66 — The baseline path is protected against *writes*, but nothing prevents an agent from deleting or renaming it via shell commands, which resets acceptance state and makes every known poisoning finding "new" noise (or, paired with a compliant re-baseline, hides history). Suggestion: extend the guard to unlink/rename of that path where the safety layer intercepts them, and document the residual threat model in the module docstring.

- hermes_cli/security_config_scan.py (cmd_security_scan) — TOCTOU between the reviewed run and the later `--update-baseline` rerun: whatever changed in between gets accepted sight unseen. Suggestion: print each finding's fingerprint in human output and offer `--accept-fingerprint ...` (or accept-from-JSON) so operators accept exactly what they reviewed.

Suggestion: rename the flag semantics (--all-files to disable filtering) or document it in help text.
