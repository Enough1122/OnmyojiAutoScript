Solid approach overall: a single pinned manifest (sha256 for every asset), hash verification on both the Nix-provided and network-fetched paths, and a clean dev-vs-build split through the committed stub. Points to consider:

- packages/opencode/script/build.ts (resolveGrammarAsset, ~L70) — When OPENTUI_BUNDLED_GRAMMARS_DIR is set but a file is missing, the code silently falls back to a network fetch. Inside a Nix sandbox (no network) this produces a confusing fetch failure far from the real cause. Why it matters: the whole point of the env var is hermetic builds. Suggestion: if the env var is set, treat it as authoritative — throw immediately naming the missing file instead of attempting fetch.

- packages/opencode/script/build.ts (~L296-305) — Overwriting the tracked packages/tui/src/bundled-grammars.gen.ts and restoring it in a finally block means a SIGKILL/crash mid-release leaves Bun-only `import ... with { type: "file" }` syntax in a git-tracked file (and concurrent builds race on it). Suggestion: generate into a gitignored path (or temp file swapped in place) so the working tree is never mutated.

- packages/opencode/script/bundled-grammars.json — Several grammars pair a wasm from one version with queries from another ref: python (wasm v0.23.6 vs highlights from v0.25.0), swift (wasm 0.7.1 vs highlights 0.7.3), diff (wasm v0.1.0 vs highlights v0.2.0). Tree-sitter queries referencing nodes renamed between versions fail at query-compile time and take down highlighting for that language. Suggestion: align each grammar's wasm and query refs to the same tag, or add a smoke test that compiles every query against its pinned wasm.

- packages/tui/src/parsers-config.ts (bundledAsset) — Dev silently uses remote URLs while compiled binaries use embedded assets, so the two modes can render different highlighting (the manifest intentionally switched some query sources, e.g. python highlights moved off tree-sitter-python master). Suggestion: log once at startup which mode resolved, so user reports like "highlights look different in dev" are diagnosable.

- packages/opencode/script/build.ts (~L88-105) — All ~80+ assets are fetched via unbounded Promise.all; release machines can hit GitHub raw rate limits (429), failing the whole build. Suggestion: cap concurrency (e.g. 8) with a tiny pool helper.

A future filename like "c-sharp-tree-sitter.wasm" would diverge silently. Suggestion: a CI test asserting the Nix grouping equals the TS grouping over the manifest.
