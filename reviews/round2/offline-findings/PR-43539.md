# PR 43539 — fix(app): show header for untitled sessions

## 标题/作者意图
作者 Rexarrior。修复 #42821:时间线顶栏的显示条件原来是 `titleValue() || parentID()`(即"有标题或是子会话"),新建的根会话在标题生成完成前 title 为空,导致顶栏(含 "More options" 等操作按钮)消失。改为以 `sessionID()`(路由中的会话 ID)为门控:已持久化的未命名会话保留顶栏,无 ID 的草稿仍不显示。

## 改动概览
- 2 个文件,+31/-1,无截断。
- 核心改动:`packages/app/src/pages/session/timeline/message-timeline.tsx:332` 一行逻辑改动(`showHeader = !!(titleValue() || parentID())` → `!!sessionID()`)。
- 新增 e2e 回归测试 `packages/app/e2e/regression/session-timeline-header.spec.ts`(30 行):断言持久化未命名会话的 `[data-session-title]` 与 "More options" 按钮可见、草稿路由下顶栏计数为 0。

## 发现的问题

### P0(正确性 bug)
未发现。

### P1(边界/回归风险)
未发现明显问题。已核对 base 提交(df35e842)上 `message-timeline.tsx` 的完整上下文确认语义:
- `titleValue = info()?.title`(base:299)在草稿下为 undefined,`sessionID = params.id`(base:277)在草稿路由下为 undefined,所以草稿行为不变,与 PR 描述一致。
- 子会话(parentID 有值)必然有 sessionID,行为不变。
- 顶栏 JSX(base:1369 起)内部标题经 `<Show when={childTitle() || title.editing}>` 自行隐藏,空标题时只渲染操作按钮区,与"保留 header 不新增视觉态"的意图一致;`openTitleEditor`(base:765)自带 `sessionID()` 守卫,空标题点击无副作用。

### P2(风格/小问题)
- `message-timeline.tsx:332`:新门控基于 URL 路由参数 `params.id` 而非已加载的会话数据。若 URL 带有已被删除/失效的 session id,旧逻辑(info 未加载 → titleValue undefined)不显示顶栏,新逻辑会渲染出顶栏,"More options" 菜单内的会话操作将作用于不存在的会话(多为 no-op 或报错提示)。影响很小,且"数据未到先显示顶栏"本就是本 PR 想要的行为,仅提示作者知晓该边界。

## 一句话总评
极小且聚焦的 bug 修复,改动语义经核对无回归面,附带 e2e 回归测试,值得上游采纳;唯一注意点是门控改用路由参数后,失效会话 ID 的 URL 也会渲染顶栏。
