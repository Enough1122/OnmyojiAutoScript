This PR adds generic producer-attached action buttons for Telegram: `metadata["buttons"]` renders an inline keyboard whose taps re-enter the gateway as a `gateway_platform_event` of type `action_button`, bound to the exact chat/topic/message/profile the keyboard was delivered on, single-use and TTL-bounded. The send-side rendering, callback dispatch, authorization chain, and the `base.py` notice-sanitizing change are all carefully constructed, and the test coverage (authz boundaries, reservation, commit-on-delivery) is thorough.

Points:

1. Tap authorization is fail-closed where the message path fails open. `_is_callback_actor_authorized` (`plugins/platforms/telegram/adapter.py:1476`) denies when neither `TELEGRAM_ALLOWED_USERS` nor `GATEWAY_ALLOW_ALL_USERS` is configured, while `_is_user_authorized_from_message` still returns `True` for setups that never configured env auth (the existing `if not self._telegram_auth_env_configured(): return True` escape). An operator running a default-allow bot will see every action button answered "not authorized" even though typed messages work. That is a defensible security posture, but it is a divergence from the message path that won't be obvious; the `action_button` docs entry added in `website/docs/user-guide/features/hooks.md` doesn't mention the auth requirement, so operators may debug it as a broken button. Consider documenting the fail-closed default explicitly.

2. Registry eviction is FIFO by insertion order, not earliest expiry. `_commit_action_buttons` (`plugins/platforms/telegram/adapter.py:5467`) pops from the front of the dict once the 512 cap is crossed, regardless of remaining TTL. A producer that delivers more than 512 buttoned messages within the 10-minute window evicts still-valid buttons on other messages. Minor since the cap/TTL is documented, but evicting the soonest-expiring record would preserve live buttons longer under high volume.

3. Expired records are purged only opportunistically. The stale sweep runs inside `_commit_action_buttons` (`plugins/platforms/telegram/adapter.py:5465`) and `_pop_action_button` drops only the single nonce it looked up. On a low-traffic bot, entries can outlive their TTL in memory until the next commit. Bounded at 512, so not a leak — just latent state. Minor. A small sweep on the tap path would keep the registry honest.

Also minor: `_pop_action_button` removes the record before checking expiry (`plugins/platforms/telegram/adapter.py:5549`). The record is gone either way so this is correct, but the ordering means the "expired" answer depends on the post-pop check — worth a comment noting it's intentional if so.
