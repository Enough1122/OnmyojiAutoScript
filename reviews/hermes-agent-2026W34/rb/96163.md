This PR lets the Desktop New Bot form accept CJK/mixed-script names by deriving a deterministic ASCII profile slug (`-u<hex>-` per non-ASCII letter/digit) while preserving the entered name as the display title. The design correctly leaves the shared group-chat `slugify` untouched and routes all creation paths through the new `botProfileIdentity`. Regression tests cover pure CJK and mixed inputs.

- `apps/desktop/src/plugins/hermes-bots/labels.ts:77` — `slugifyProfileName` is deterministic but not injective: `小助手` and the literal ASCII string `u5c0f-u52a9-u624b` both map to the same profile slug. A user could name a bot exactly `u5c0f-u52a9-u624b` and it would collide with the CJK-derived ID. This is inherent to the ASCII-contract design, but it's worth consciously accepting and documenting, and a test pinning the ASCII-lookalike collision would make the trade-off explicit. Minor.

- `apps/desktop/src/plugins/hermes-bots/labels.ts:104` — the title fallback compares `enteredName !== slug` case-sensitively, so `Test` (slug `test`) becomes the title while lowercase `test` (slug `test`) does not. Slightly inconsistent, but harmless since the title is display-only. Also, a 64-char name whose slug is truncated can cut a `-u<hex>-` token in half; deterministic and functionally harmless, but an edge case a test could pin.

- Test gap: a symbols-only name (e.g. `🤖`) yields an empty slug and disables Create Bot via the `valid` check — worth a small assertion to lock that in, since the new function is what now decides button state.
