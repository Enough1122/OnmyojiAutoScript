This PR fail-closes `open_preview` for directory targets: `_is_existing_directory()` (tools/open_preview_tool.py:62) detects local directories (including `file:` URIs) and the guard at tools/open_preview_tool.py:83 returns an explicit error without emitting `preview.open`, while files, HTTP(S) URLs, and missing paths behave as before. Tests cover existing dir, existing file, HTTPS URL, file-URI dir, and missing path. A contributor email file matching the existing `contributors/emails/` format is also added.

Points:

- (minor) Relative-path targets now resolve against the backend process's CWD: `Path(raw).expanduser()` at tools/open_preview_tool.py:59. Previously the tool passed the raw target straight to the renderer, so the new check introduces a server-side dependence on the process working directory (in a gateway context this is `terminal.cwd` from config, which may differ from where the desktop client's user believes the file lives). If a relative path happens to point at a directory in the backend CWD, it will be rejected even though the renderer would have resolved it elsewhere. Worth documenting that targets should be absolute, or resolving relative to a defined base.

- (minor) The fail-open `OSError` branch in `_is_existing_directory` is deliberate and documented, but untested. A short test that monkeypatches `Path.is_dir` to raise (permission error / broken reparse) would pin that behavior so a future change doesn't turn an unexpected stat failure into a spurious rejection.

- (very minor) The Windows-style `file:///C:/…` normalization is gated on `os.name == "nt"` (tools/open_preview_tool.py:53-57), so a Windows URI passed to a non-Windows backend won't be normalized and fails open. Acceptable for a desktop-local tool, just noting the asymmetry.

The missing-path and HTTPS-URL tests are a good match for the intent: only *positively observed* existing directories are rejected.
