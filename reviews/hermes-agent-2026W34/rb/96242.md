This PR adds a hot-import path for the desktop prompt-templates store: a watcher (`prompt-import-inbox.ts`) polls `$HERMES_HOME/prompt-templates-inbox/*.json`, parses a small job schema, merges/replaces templates into the live store, and archives applied/failed files, plus a bash helper to enqueue jobs. The import/dedupe logic is static (normalize + token Jaccard), with no LLM involvement.

The import flow is cleanly separated (parse → apply → archive) and well unit-tested, but a few state/robustness issues are worth addressing:

1. **`seen` set is never pruned and is keyed by path — a re-dropped job with the same filename is silently skipped forever.** `seen.add(path)` happens at `apps/desktop/src/store/prompt-import-inbox.ts:137` before processing and the module-level set (line 13) never has entries removed. Processed files are moved to `applied/`, so if a writer uses a fixed filename (e.g. always `job.json`), the original path reappears in the inbox listing on a later drop but `seen.has(path)` at line 133 skips it permanently. Since files are archived out of the inbox after processing, the `seen` set appears redundant for the normal flow and actively harmful for repeat writers — it could be dropped, or pruned once the path no longer exists in the listing.

2. **A transient read/parse failure permanently loses the job.** In `processInboxOnce`, if `readJob`/`parsePromptImportJob` returns null (line 139) — e.g. the writer is still flushing the file when the 2s poll fires, or the read is truncated — the job is immediately archived as failed and the original trashed at `apps/desktop/src/store/prompt-import-inbox.ts:142`, so the next poll never retries it. The shipped bash helper writes non-atomically (`open(job, "w")`), so this race is reachable. Consider leaving unparseable files in place (or rename to a `.bad`/`.retry` suffix) and retrying next tick, archiving only on success.

3. **`op: "replace"` wipes the store before processing, so a mid-loop failure leaves the store emptied.** `setList([])` runs first at `apps/desktop/src/store/prompt-import.ts:155`; `parsePromptImportJob` validates template shape, but `ensureFolderByLabel`/`addTemplate` can still throw mid-loop, losing the user's existing templates with no recovery. Building the new list first and only swapping it in after all templates succeed would keep `replace` atomic.

4. **Minor — hardcoded CJK markers bypass the app's i18n.** `PROMPT_IMPORT_MARK_DUP`/`PROMPT_IMPORT_MARK_NEAR` at `apps/desktop/src/store/prompt-import.ts:16-17` and the description prefix at line 231 are literal `〔重复〕`/`〔相近〕` strings, while the app ships ar/en/ja/zh-hant/zh locales. Non-Chinese UI will render Chinese marks on near-duplicate imports.

5. **Minor — dead no-op branch in `archiveJob`.** The `if (desktop?.renamePath) { ... }` block at `apps/desktop/src/store/prompt-import-inbox.ts:104-106` contains only a comment and does nothing; it can be removed (the comment can move to the `trashPath` path).
