This PR fixes a `session_search` SCROLL retry-loop: when `_scroll()` finds no messages for a guessed/stale `around_message_id`, it now returns a bounded session read tagged with a `scroll_recovery` block (naming the rejected id and telling the model to use only real anchor ids) instead of a retryable tool failure. The design is sound — recovery keys are emitted before the transcript so they can't be missed on a long read, and a failed recovery read falls through to the original error path (`session_search_tool.py:664` guards on `fallback.get("success")`, so an exception → `{}` → original `tool_error`).

Minor: the recovery reason is hardcoded to `invalid_around_message_id` for every empty `messages` result, but that branch can also fire when the anchor is valid and the session is empty, or when a window edge lands on no messages. The bounded-read fallback is the right move in all of those cases, so it's safe — but the diagnostic ("The requested message id is not in this session") can be misleading outside the true invalid-anchor case. A wording tweak that also covers "session has no messages here" would keep the model from chasing the wrong cause.

The returned bounded read is always the default head=20/tail=10 window. Acceptable and consistent with "bounded read", but worth a comment that the recovery deliberately ignores the requested window so the behavior isn't mistaken for a bug.

3. Test gap: the new test covers the invalid-anchor path, but not the preserved failure path — a non-existent `session_id` (where `_read_session` raises → `fallback = {}` → original `tool_error`). The PR explicitly claims recovery never masks a real error; a small test asserting a nonexistent session still returns the plain failure (no `scroll_recovery` key) would lock that claim in.
