# 鹈鹕骑士 · 喉囊弹匣 — 设计文档

日期：2026-09-24
状态：已批准，待写实现计划

## 1. 目标

一个双击 HTML 文件就能玩的鹈鹕骑车网页游戏。跑酷底子 + 只属于鹈鹕的创意机制：**喉囊是弹匣**——自动吞、手动吐，吞进去的东西变成招式。

**成功标准**

- 30 秒内上手，无需读说明
- 喉囊机制在第一局就被自然理解（不需要教程文字）
- 有重开欲望（最高分可见、可破）

**硬约束**

- 单文件 HTML，零外部资源（无图片、无音频文件、无 CDN）
- `file://` 双击直接可玩
- 现有 `projects/pelican-bike/pelican-bike.html`（CSS 动画插画）保留不动，游戏另起文件

**不做（YAGNI）**

手机触屏、排行榜、多角色、关卡模式、存档进度、道具商店、多人。

## 2. 核心循环

骑车自动前进 → 嘴一直张着，碰到道具自动吞进喉囊 → 跳过/蹲下躲障碍 → 按空格吐，吐什么决定发生什么 → 囊满则吞不进新的 → 撞 3 次摔车结算。

## 3. 喉囊机制

容量 **6** 格，**FIFO 队列**（吐最旧的）。

选择 FIFO 而非「任选吐哪个」，是为了让决策保持在一维：**什么时候吐、吐几个**，而不是在高速下还要选目标。

| 吞入 | 吐出效果 |
|---|---|
| 🐟 鱼 | 前飞，击落乌鸦 |
| 🪨 石头 | 前飞，砸碎并穿透障碍 |
| 🌶️ 辣椒 | 喷火冲刺 1.5s：无敌 + 加速 + 撞碎一切 |
| 🫧 泡泡 | 浮空 4s，期间可再跳两次（共三段）；落地或超时后重置 |
| ⭐ 星星（稀有） | 清除屏幕上全部障碍，每个障碍 +10 分，另加 +50 分 |

**囊满时**：新道具直接穿过（错失），不扣命、不扣分。惩罚是机会成本，不是死亡。

**得分时机**：鱼在**吞入时**结算 +10 × 倍率。吐出鱼不加分——吐鱼的价值是清格 + 击落乌鸦，不是分数。这样「清掉鱼去够石头」是纯粹的时间成本，决策干净。

## 4. 障碍

| 障碍 | 应对 |
|---|---|
| 🗑️ 垃圾桶 / 🚧 路障 | 跳 |
| 🐦 低飞乌鸦 | 蹲，或用吐出的鱼击落 |
| 🕳️ 坑洞 | 跳（速度越快越难）；掉进去按撞车处理，掉 1 命 |
| 🧱 高墙 | 石头砸 / 辣椒冲 / 泡泡浮空过 |

## 5. 数值

**画布**：逻辑分辨率 960×540，按窗口等比缩放，处理 devicePixelRatio。
**坐标系**：世界向左滚动，鹈鹕固定在屏幕 x = 220，地面 y = 430。

**物理**

| 项 | 值 |
|---|---|
| 重力 | 2200 px/s² |
| 跳跃初速 | −780 px/s（最高约 138px，滞空约 0.71s） |
| 泡泡额外跳 | 每段初速 ×0.85 |
| 蹲下碰撞盒高 | 78 → 42 |
| 蹲下速度 | ×0.55 |

**速度**

```
difficulty = min(t / 90, 1)          // t = 本局秒数
v = 340 * (1 + 1.5 * difficulty)     // 340 → 850 px/s
冲刺时 v × 1.9，持续 1.5s
```

**生成**

```
gap = lerp(520, 260, difficulty) * (1 ± 0.15)   // 像素
道具权重：鱼 65% / 石头 15% / 辣椒 10% / 泡泡 7% / 星星 3%
鱼按 3–5 个一组的弧线串出现
```

**计分**

```
距离分 = floor(distance / 10)                 // 不乘倍率
鱼分   = 10 * 倍率
streak 每吞一条鱼 +1，撞车归零
倍率   = clamp(1 + floor(streak / 10), 1, 5)
```

**命**：3 条。撞车流程：进入 `crashed` 状态 0.3s（慢动作）→ 回到 `playing` 并开始 1.5s 无敌闪烁；速度立即降到「当前难度速度 × 0.6」，再在 1.2s 内线性恢复到 1.0x。命掉光进入 gameover。

**状态叠加规则**

- 蹲下不阻止吞入，只把碰撞盒变矮
- 冲刺期间可跳可蹲；冲刺自带无敌，与受击无敌各自独立计时，不叠加、不互斥
- 冲刺期间吞入的道具照常进囊
- 无敌闪烁期间撞障碍不掉命，但障碍本身不消失（只有冲刺和石头能清除障碍）

## 6. 状态机

```
title → playing ⇄ crashed(0.3s 慢动作) → gameover → playing
playing ⇄ paused
```

最高分存 localStorage，key `pelicanRunner.best`。

## 7. 输入

| 键 | 动作 |
|---|---|
| ↑ / W | 跳（泡泡期间可再跳两次） |
| ↓ / S | 蹲 |
| 空格 | 吐 |
| P / Esc | 暂停 |
| R | 重开 |
| M | 静音 |

空格给「吐」而不是「跳」，是有意为之：吐是本作的核心动作，拿最大的键。跳用 ↑/W，方向键区符合直觉。

## 8. 手感（决定「好玩」的部分）

- **吞**：喉囊鼓一下 + 音高随 streak 递升
- **吐**：后坐力位移 + 拖影
- **跳**：起跳压扁、落地拉伸（squash & stretch）
- **撞车**：羽毛飞散粒子 + 0.3s 慢动作 + 震屏
- **辣椒冲刺**：屏幕闪白 + 速度线拉满 + 持续震屏
- **车轮**：转速与当前速度严格成正比
- **腿**：踩踏相位与车轮角度绑定，不独立循环

## 10. 音频

Web Audio 程序化生成，无音频文件。

| 事件 | 声音 |
|---|---|
| 吞 | 正弦上滑 220→440Hz，80ms |
| 吐 | 噪声 burst 下滑，120ms |
| 跳 | 方波上滑 330→660Hz，90ms |
| 撞车 | 低频噪声 + 下滑，250ms |
| 得分 | `440 * 2^((streak % 8) / 12)`，音高随连击递升 |
| 辣椒 | 白噪扫频 + 低频轰鸣 |

AudioContext 在首次用户输入时创建（浏览器自动播放策略要求）。

## 11. 技术架构

**单文件**：`projects/pelican-bike/index.html`。

为什么是单文件——`file://` 下 ES modules 会被 CORS 拦截，双击打不开。这是硬约束推导出的结果，不是图省事。

文件内部按层组织，纯逻辑在上、渲染在下：

```
纯逻辑（可测）   pouch 队列 / 计分连击 / 难度曲线 / 生成权重 / 碰撞判定
状态机           title → playing ⇄ crashed → gameover
渲染层           Canvas 2D 程序化路径
音频层           Web Audio 程序化
粒子层           对象池，避免每帧分配
主循环           requestAnimationFrame + 固定步长累加器
```

纯逻辑必须是不依赖 DOM/Canvas 的纯函数，否则 `?test=1` 测不了。

## 12. 测试与验证

跑酷游戏不好整体单测，但纯逻辑层可以。内置 **`?test=1` 自检模式**：同一个文件，打开 `index.html?test=1` 跑断言，把 PASS/FAIL 画在页面上并输出到 console。这样既保住单文件约束，又有真实可跑的验证。

断言清单：

1. pouch FIFO —— 吞入顺序等于吐出顺序
2. pouch 容量 —— 第 7 个吞入被拒（返回 false），长度仍为 6
3. 吐空囊 —— 返回 null，不抛异常
4. 倍率曲线 —— streak 0→x1，10→x2，40→x5，100→x5（封顶）
5. 撞车清零 —— streak 与倍率归位
6. 难度曲线 —— t=0→1.0x，t=90→2.5x，t=200→2.5x（封顶）
7. 碰撞盒 —— 蹲下后原本会撞的空中障碍变为不撞
8. 生成权重 —— 10000 次采样，各道具占比在期望 ±3% 内
9. 距离分公式 —— 边界值

**验收标准**（可观测）

- 双击 `index.html` 在 Chrome/Edge 能直接开玩，控制台无报错
- `?test=1` 全部 PASS
- 一局能跑到速度 2.5x
- 喉囊满 6 格后不再吞入
- 空格吐出的石头能砸碎高墙
- 刷新后最高分仍在

**如实报告的边界**：自动化只能验逻辑与无报错；「好玩」和手感由实机试玩确认，我会说明验了什么、没验什么。
